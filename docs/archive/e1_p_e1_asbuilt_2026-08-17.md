### §2.1.2 — the transient energy accumulator

`e[i] = (int64)n_bulk_pre[i] · (int64)T_raw[i]`, exact and unshifted, built
per substep in `bulk_flux_energy_transport_cached` (`bulk_transport.cpp`).
Participation predicate (`e_participates`, one transcription, mirrored as
`e_part_dev` on the device): `!solid && !ts && !is_vacuum && !ring`.
Non-participants carry `e = 0` and are never read. The `N < 2^30` map
invariant carries a debug `assert` at the build, per L2-5. The three scratch
planes (`e_scratch_`, `dqsum_e_`, `dqsum_s_`) are `mutable std::vector<int64_t>`
members — transient, never synced, never digested (R4).

### §2.1.3 — energy rides the APPLIED flux

`bulk_flux_transport_cached` gained two trailing `int64_t*` face planes
(default `nullptr` ⇒ byte-identical legacy path). They accumulate the
per-face `dq` summed over the conservative planes **after the outflow limiter
and after `scale_mag`, before the divergence apply** — the exact placement
L1-10/L2-2 pinned, so the energy rides the mass the books actually move, not
the pre-limiter intent. Sign(dq) == sign(v_face) on every face and plane, so
the donor the energy pass reads off the sum's sign IS the donor each plane's
own flux chose.

Stage 3 is **gather-form**: each cell edits only its own `e`, reading its four
touching faces in the pinned order **E, W, S, N**. int64 sums are
order-immaterial; the order is pinned anyway because the twins must transcribe
one expression order (L2-11). No atomics are needed for the energy itself —
only the VALUE-SUM counters use int64 `atomicAdd`, which is order-free on
two's complement.

### §2.1.4 — ts-face rule (d), per-face, exactly as ruled

- **air→ts**: `e[donor] -= dq·T_rel[donor]` (donor priced at its OWN T, so its
  recovered T is exactly invariant as mass leaves — no concentration mint),
  and the debited amount accumulates in the SIGNED `e_ts_residual`.
- **ts→air**: the receiver is credited **zero** — mass emerging from an object
  carries no relative energy.
- **ts→ts**: nothing.
- Implementation note: the DONOR side is uniform (a participating donor is
  always debited at its own T); the RECEIVER side is conditional on the donor
  participating. That single asymmetry expresses rule (d), the §5
  born-at-ambient class rule for vacuum/ring emergence, and the "boundary
  channels stay uncounted" ruling all at once. Reading `participating[j]`
  rather than `T[j] == 0` is deliberate: it does not depend on a stale wipe
  value surviving from a previous pass.

### §2.1.5 — recovery, guards, counters

`T[i] = floordiv_q(e[i], n_bulk_new[i])` using the **shared** FP_HD helper now
living in `fixed_point.h` (§2.7 pins it there; §2.1.5 shares it — one
transcription, used by both, exactly as v2.2 requires):

```cpp
FP_HD inline int64_t floordiv_q(int64_t n, int64_t d) {
    int64_t q = n / d;
    if (((n % d) != 0) && ((n ^ d) < 0)) --q;
    return q;
}
```

The header comment states why plain `/` is a silent minter and why
**CPU↔CUDA parity gates cannot catch it** — both backends truncate toward
zero and agree with each other; only the ledger can see it.

Guards, each with an energy counter:
- `n_bulk_new < N_EPS` (1 raw count) → `T := 0`, residual into signed `e_wipe_sum`;
- `T_MIN` clamp on recovery → energy CREATED, counted in `e_floor_sum` (a
  CREATOR under R3);
- solid and ts cells are never written (the T-WRITE guard, upheld);
- vacuum / ambient-ring cells keep their per-substep `T := 0` wipe, moved here
  **verbatim** from the retired SL write — semantics unchanged;
- the ring's N reset is untouched (still inside the mass pass).

New counters, all `int64`, all `def_readonly`, all reset at `step()` entry
(the `boundary_flux_` idiom) so each read is that tick's delta:
`e_ts_residual` (signed), `e_wipe_sum` (signed), `e_floor_sum`,
`n_active_flux`, `n_bulk_active_sum`. All five are wired into
`tools/storm_ledger.py`'s `counters()` and into `PER_TICK_COUNTERS` (so the
run totals accumulate them instead of diffing them).

### §2.1.6 — the digest move (declared re-baseline-class)

`digest_advect` hashed `(wx, wy, T)` at the last substep **BEFORE** the flux
call. It now runs **AFTER** the energy transport, because the T it must hash —
T after recovery — only exists there. The expression itself is unchanged.

**Old**: `digest_of(wx, digest_of(wy, digest_of(T_after_SL, 0)))` taken
between step 1b and step 1d.
**New**: the identical expression taken after step 1d.

Coherence across paths: the per-call CUDA path already computed
`digest_advect` post-substep-loop (it was equal to the CPU's mid-loop value
only because the flux used not to touch u/T), so it needed **no** change and
the two now agree for the new reason. The resident path stores no digests.
`digest_bulk_flux` is unmoved.

### CUDA structure

Five new kernels in `cuda_bulk_transport.cu`, each the CPU loop of the same
name transcribed body-for-body: `bulk_dq_accum` (stage 2c, launched between
B3 and B4 — precisely where the CPU banks the applied dq), `bulk_nb_accum`,
`bulk_e_build`, `bulk_e_apply`, `bulk_e_recover`. Host orchestration
`bulk_flux_energy_transport_device` runs the four stages; **stage 2's
per-plane chain is the UNCHANGED B1..B5 mass pass**, which is why gas planes
stay byte-for-byte what they were. Scratch: `e`, `nbulk`, `dqsum_e`,
`dqsum_s` (int64 h·w each) + a 5-slot counter block, added to
`EOSResidentScratch` and to the per-call allocator. `EOSHostPrestage` gained
the shared `t_min_q` fold so both dispatch paths read one transcription.

## 2. Contract changes (authorized rewrites)

- **`eos_sl_advect_reference` is u-ONLY.** `temperature` is now a read-only
  src slot for the fused sampler (its `.t` is discarded, exactly as in
  `step()`; `.vx`/`.vy` do not depend on the third array, which is why the

  u stays bit-identical to HEAD). The return is the chained FNV over

  `thermal_solid` is kept for ABI and ignored.

  temperature is never written and never read back; the digest is u-only.
- **`sl_advect3_device`** loses the five T-only parameters.
- **`bulk_flux_plane_device`** gains two optional trailing int64 planes.

## 8. The one carried red — `test_ambient_gate3_udamp_band_absorbs_reflection`

**Not fixed, not rewritten, reported.** This is a trajectory-coupled boundary
gate that Appendix A listed under "Expected stable", so it does not fall under
any authorized-rewrite class, and it is feel-adjacent (it is the sponge
band's absorption gate). It is left red for Erik's boundary decision rather
than retuned by an implementation agent.

What it asserts, and what happened:

- leg (a) `absorbed < 0.75 · pin_only` — **FAILS**: `pin_only = 0.0081`,
  `absorbed = 0.0079`.
- leg (b) `absorbed <= 0.02` (the ≤2 % reflection gate, the actual safety
  property) — **PASSES**, with a 2.5× margin.

Both legs are two runs of the same post-patch code. The failure is not that
absorption got worse in absolute terms; it is that the **pin-only baseline
collapsed to 0.81 %**, leaving the band no 25 % of headroom to cut. The
mechanism is the expected coupling: the transport law changes T evolution →
changes p* → changes the acoustic field the reflection metric probes.

**What this needs from Erik**: a ruling on whether leg (a)'s *relative* form
still expresses anything once the pin-only reflection is at the noise floor,
or whether the gate should become absolute-only. That is a gate-semantics
decision, not an implementation one. (Pre-patch values for `pin_only` are
recorded in §11.)

   of the 2-5 min band at its lower edge). The fire peaks ~13 % sooner.
2. **`flame plateau T` 390 -> 387 game (−0.8 %)** — the predicted (critique
   L1-5) "cooler/weaker" direction, and it is **small**: the flame lost under
   one percent of its plateau temperature, not a regime change. It was
   already a MISS against the 400-500 target before this patch and still is,
   by about the same distance.
3. **`far-field T rise` 0.6 -> 0.0 — a WIN, and the mint made visible.**
   Far-field cells used to warm by 0.6 game-deg with no energy ever having
   been delivered to them; that was the SL copy writing phantom T onto real
   mass at range. It is now exactly zero.

`peak I`, `room N_total min`, `far-field X min`, `local X min` and `wall_hp`
all moved by <= 0.5 % — the O2 anchors in particular did not move, which is
exactly what §5's 0-LSB conservation result predicts.

**For Erik's boundary decision (re-tune vs MacCormack fallback):** the
patch's anchor cost is one verdict flip (`peak time`) plus a −0.8 % plateau
temperature, against the phantom far-field heating going to zero. Nothing
here was retuned — `k_grow` / `k_die` / `wall_damage` are the dials that own
`peak time` and `fire death`, and both were already MISSing for pre-existing
reasons.

## 11. Deviations from the brief, summarized

1. **The canonical shared golden did NOT move again** (§7). It was predicted to
   move and be re-baselined; measured byte-identical to P-T0's value, because
   the A/B scenario carries `temperature` identically 0 in every cell on every
   tick, which makes this law an exact no-op there. Verified by probe, not
   assumed. No new digest is recorded at this rung.

2. **One red is carried unfixed and returned to Erik**:
   `test_air_boundary::test_ambient_gate3_udamp_band_absorbs_reflection` (§8).
   Appendix A listed `test_air_boundary.py` as "Expected stable", so this sits
   outside every authorized-rewrite class, and the gate is feel-adjacent — an
   implementation agent quietly retuning it would be exactly the silent change
   the project forbids. **Measured on both sides of the patch:**

   | | pin-only ring | with the u-damping band | ratio | leg (b) <= 2 % |
   |---|---:|---:|---:|---|
   | PRE (HEAD 824745c) | 0.02187 | 0.01264 | 0.578 | PASS |
   | POST (P-E1) | **0.00810** | **0.00791** | **0.977** | PASS |

   Both reflection figures got **much better** in absolute terms — the
   pin-only ring alone now meets the <= 2 % gate, which it previously did not
   by itself (2.19 %). The relative leg `absorbed < 0.75 * pin_only` fails
   only because the baseline it divides by collapsed by 63 %: there is almost
   nothing left for the band to absorb. The decision Erik owns is whether leg
   (a)'s relative form still expresses anything at this noise floor, or
   whether the gate should become absolute-only.

3. **Four premise-test rewrites BEYOND Appendix A's P-E1 list** (§7 table):
   the three `test_eos_step1b_*` tests and
   `test_thermal_solid_blocks_gas_T_advection_across_the_tile` in
   `test_thermal_mass_axis.py`, plus `cuda_thermal_mass_eos_check` PART 1a's
   mask-is-live control. Appendix A named `test_thermal_mass_axis.py` only
   under "trajectory-coupled, must stay green **or be re-derived**"; these
   were re-derived. Each asserted the behaviour of a mechanism §2.1.1
   retires, and each is replaced by the stronger guarantee the new law gives.
   Reported per the spec's standing "report any site this list missed".

4. **The `eth_transport_delta` / `eth_compression_delta` bracket counters were
   NOT ported to the CUDA dispatch paths.** §2.5 says "CUDA twins ride P-E1";
   they do not, and this is a deliberate, reported omission rather than an
   oversight. Rationale: those two are pure instrumentation, digest-inert, and
   read by no parity gate (the lockstep `_COUNTERS` tuples list only the five
   rail counters); `tools/storm_ledger.py` and every gate that consumes them
   run on the CPU backend. Porting them means a full-grid device reduction
   twice per substep — real cost and real new surface — for an observable
   nothing on that backend reads. **The five NEW P-E1 counters ARE on both
   backends** and are gated bit-identical CPU<->GPU (§6, bulk-flux PART 3),
   which is what the law change actually needed. If a GPU-side ledger is ever
   wanted, this is the named gap.

5. **`TemperatureSolver` Pass 0b was retired by DELETION, not by a
   hard-assert** — the design allowed either, and named the assert as the
   option for "if a caller can pass wind". Verified first: a caller CAN
   (`TemperatureSolver.step` / `cuda_temperature_step` both expose optional
   `wind_x`/`wind_y`), and one of those callers is a live suite test. An
   assert would have thrown for it. Deleting on both backends identically
   keeps the two in agreement and makes the pass a silent no-op instead.
   Reported because the design's phrasing implied the assert was the safer
   branch here.

6. **`bulk_transport.cpp`'s N<0 -> 0 clamp is left as-is**, per §2.1.5's
   ruling: it creates mass against a fixed `e`, so it can only DILUTE the
   recovered temperature. Benign, stated, uncounted.

7. **The patch landed in two code commits (CPU half, then CUDA half) rather
   than one.** The brief asked that the tree never be parity-broken at any
   commit; it also insisted on committing at every green point, after two
   attempts had been lost with nothing committed. The CPU half was committed
   the moment its own gate went green and the CUDA half landed immediately
   after, with no other arc commit between them — so the branch is
   parity-whole at HEAD and the parity-broken window is one commit wide and
   explicitly labelled in its message.
