# Heightmap refinement tool — design

**Status:** design in progress, co-written with Erik (2026-06-13). NOT canon, NOT built. v2 — Erik's
first round of comments folded in (marked **[E]**); open threads at the end. On approval it becomes a
tool + (the format/scale parts) canon in the graphics/level chapters.

---

## 1. The problem

The per-level **heightmap** (per-pixel floor relief) is generated by a single global Depth-Anything
pass over the whole ship art. It now drives the **ship's normal-mapped lighting** *and* the **water's
per-pixel depth** (protrusion/pooling), so its quality is load-bearing. A single global pass has three
weaknesses, all of which Erik hit:

1. **Low local detail.** The model sees the whole 3900×6456 ship at once → fine features (console
   buttons, crate edges, debris) come out mushy.
2. **No "level 0."** Depth-Anything emits *relative, per-image-normalized* depth, so the floor sits at
   an arbitrary nonzero value → the "fill forever" water bug (patched by the `height_floor` dial; the
   cure is baking a real zero in).
3. **No real scale.** The relief is 0–1, not metres — so heights have no physical meaning, and the
   water depth interaction isn't grounded.

## 2. The tool — an in-game heightmap inspector + region editor

A pyray tool (extending `align_level_art.py`'s viewer/coords). The UI **[E]**:

- **Camera pan/zoom** — move around the ship freely.
- **Layer toggle** — choose which art layer you're inspecting: **base / furniture / destroyed**.
- **View toggle** — flip between **ART ↔ HEIGHTMAP ↔ NORMAL** for the selected layer, so you can spot
  where the heightmap is missing detail or wrong against the art that produced it. **[E]** The combo
  that matters most is *heightmap + normal together* — add a blended/overlay view of those two (the
  relief + how it lights) since that's what reveals whether the surface reads right.
- **See the heights [E]** — the HEIGHTMAP view renders heights *legibly*: a colour ramp + a legend,
  and a **hover-probe** that prints the height (in metres, via §4's scale) at the cursor. So you can
  read "this crate is 0.5 m" rather than guessing from a grey blob.
- **Select tool [E]** — box-select a region (the select tool is always equipped, or armed with a key
  — *open Q*). Drag a box; **right-click deselects**; a **Crop** button/key commits it.
- The crop's **art-space pixel rect, per layer [E]**, is saved to a sidecar (`<layer>_patches.json`)
  and fed to the regen — so refinements are reproducible and re-runnable.

## 3. Regen — crop, NOT upscale [E]

**Correction from Erik: we do not upscale anything.** We crop the selected region from the *original*
(already-final) art and regenerate the heightmap for *just that crop* — the win is purely that a
smaller crop fills the depth model's fixed input with *fewer features*, so each gets more detail. No
upscaling step.

- **Yes, the generator has knobs to play with [E].** `tools/depth_to_normal.py` already exposes
  `--model` (Depth-Anything **Small / Base / Large**), `--strength` (relief gain), `--invert`,
  `--flip-g`; we can add contrast / blur / bias. So you tune the regen per region.
- **Yes — generate while watching the result in the tool [E].** A **live regen-preview loop**: hit
  generate, the new patch shows *in place* (overlaid on the art / the old heightmap), tweak the knobs,
  regen, iterate until satisfied — *then* merge. Nothing is committed until you like it.
- The regen produces a fresh local heightmap for the crop; the *merge* (§5) turns it into added
  detail on the global map.
- **The pipeline tracks every coordinate end to end [E].** From the moment of selection, it records
  the art-space rect *per layer*, the crop's origin/size, and the exact merge-back position — so the
  whole start-to-finish chain (select → crop → regen → align → merge → save) is reproducible, and a
  patch can be re-run or re-merged without re-selecting. The sidecar `<layer>_patches.json` is that
  ledger (one entry per refined region).

## 4. Level 0 + a 0–1 → metres map [E]

**The heightmap data stays 0–1** (the PNG is fine as-is). What we add is a **mapping function** that
says where 0–1 sits "in the grand scheme of things" **[E]** — `metres = relief × metres_per_unit`,
with the **floor re-baselined to 0**. Two pieces, both done on the *global* map first (§6),
independent of the patch tool:

- **Level 0 — the floor baseline.** The floor is the most *common* surface, so the dominant mode of
  the relief histogram ≈ floor level. Subtract it → **floor = 0** in the 0–1 map, raised features
  positive. Set once globally; every merged patch inherits it. Retires the `height_floor` render
  fudge at the source.
- **The 0–1 → metres scale — a real-world reference [E].** Set `metres_per_unit` once from a known
  object — *"this feature is a 1.8 m human"* → solve the scale. Now `relief = 0.25` *means* 0.5 m.
  Grounds the water depth physically (a 0.4 m crate really protrudes from a 0.3 m puddle) and is what
  the height-probe (§2) displays.
- **One scale for all levels is the goal [E].** Erik: each level needn't *have* to share the scale,
  but striving for a single project-wide `metres_per_unit` (and the floor-at-0 convention) is worth
  it — *it makes swapping art/height assets between levels just work*. So the standard is: every
  level's heightmap re-baselined to floor = 0 and read through the *same* `metres_per_unit`. The
  water shader's `height_scale`/`height_floor` then become these *calibrated constants*, not eyeballed
  dials (they stay as overrides, but default to the calibrated values).

## 5. Merge — aligned, then **zero at the border** [E]

The seam is the risk, and Erik's insight fixes it robustly. The merge:

1. **Align** the regenerated patch to the global: rescale + offset it so its overall level/scale
   matches the global map *in the patch region* — so the added detail sits at the right baseline.
2. **As a delta** — the patch contributes a height *delta* (the new detail) over that aligned
   baseline, not a wholesale replacement. (This is "edit the selection by *adding* detail" **[E]**.)
3. **Zero at the border [E] — the key rule.** Force the delta to **zero at the patch edges** and
   feather it up toward the interior. Then the border pixels are *unchanged* (= the global map), so
   the transition is seamless **regardless of how good the alignment is** — the edges can't disagree
   because they're pinned to the original. Interior gets the new detail; edges are untouched.
4. **Add** the tapered delta to the global height; **re-derive the normal** from the merged *height*
   (one Sobel pass — heights merge cleanly, normals don't).
5. This is a **destructive save** to the global heightmap **[E]** (with a `.bak`), since the patch
   record persists in the sidecar for re-runs.

**Show numbers during the merge [E]** — the stats that tell you the fit is good:
- the **scale** and **offset** applied to fit the patch to the global,
- the patch-vs-global **mean / range** in the overlap ring,
- the residual **seam error** at the border (≈ 0 after the zero-border rule — if it isn't, something's
  wrong).
(If others would help once we're in it, we add them — you flagged you're unsure which; we'll learn.)

## 6. Build shape

1. **Level-0 + scale re-baseline (standalone, FIRST).** A script on the existing global heightmap:
   detect the floor mode → floor = 0; set the metric scale from a reference. Fixes the most visible
   problem (fill-forever + no scale) on the map we already have, and retires the `height_floor` fudge.
   Useful on its own, no tool needed. (`tools/heightmap_level0.py`.)
2. **The inspector** — layer toggle + ART/HEIGHTMAP/NORMAL view + the height colour-ramp/legend/probe.
   *Read* the maps before editing anything.
3. **Region select + crop export** (the sidecar rect, per layer).
4. **Regen-a-patch with the live preview loop** + the generator knobs.
5. **The aligned + zero-border feathered merge** + the numbers + destructive save.
