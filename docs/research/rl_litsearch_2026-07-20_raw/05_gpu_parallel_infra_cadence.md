# GPU-Parallel / High-Throughput RL Infrastructure & Real-Time Decision Cadence — Digest for Breach

*Raw research-agent output, 2026-07-20. Breach = deterministic, GPU-resident, fixed-point (Q16.16) engine ticking ~12–24 Hz, headless, many independent instances at once, greenfield ML layer.*

**One-sentence thesis.** Breach's structural advantage is that the environment already lives where the policy lives (the GPU). The single most important infrastructure decision is to **never leave the device**: keep sim state, observation encoding, action sampling, and gradient updates all in GPU memory, so the CPU↔GPU PCIe transfer — the dominant cost in classical RL stacks — is eliminated. Every tool below is evaluated against that principle. (First-party FPS claims = order-of-magnitude, not Breach benchmarks.)

## 1. GPU-native / massively-parallel simulators
- **Isaac Gym / Isaac Lab (Orbit)** — Makoviychuk et al. (NVIDIA) 2021, arXiv:2108.10470; Orbit Mittal et al. 2023, arXiv:2301.04195. GPU-resident PhysX exposing obs/reward/reset as PyTorch tensors; 2–3 orders of magnitude speedup; single-A100 training in hours. *Breach:* north star and near-exact analogue — expose the sim's state as a batched tensor API with a leading `num_envs` axis; pair with **rl_games** or **skrl** (PPO libs that consume it without host copies).
- **Brax** — Freeman et al. (Google) 2021, arXiv:2106.13281; github.com/google/brax. JAX rigid-body engine, differentiable; sim + PPO/SAC/ES on one accelerator via vmap/JIT/XLA. *Breach:* proves the JAX "everything compiles into one XLA program" pattern. Breach is fixed-point C++/CUDA (not differentiable the same way), but the co-location argument is Breach's thesis. A JAX-callable step (custom XLA call / dlpack from CuPy) would open the whole JAX ecosystem.
- **Madrona / GPUDrive** — Shacklett et al. (Stanford) SIGGRAPH 2023 (madrona-engine.github.io); GPUDrive Kazemkhani et al. 2024, arXiv:2408.01584. Reusable batch ECS game-engine for GPU simulators; thousands of worlds, millions of steps/sec; identical CPU debug backend; GPUDrive >1M FPS. *Breach:* closest match to what Breach IS. Transferable: (1) CPU debug backend with identical semantics — Breach's determinism makes it a bit-identical divergence oracle; (2) write observation/reward/dynamics in C++/CUDA, expose only Python handles — Breach's planned CUDA encoder. **Primary prior art to cite for the encoder.**
- **WarpDrive** — Lan et al. (Salesforce) JMLR 2022, arXiv:2108.13976; github.com/salesforce/warp-drive. End-to-end MULTI-agent RL on a single GPU (PyCUDA + PyTorch), one in-place GPU data store; 2.9M steps/s on a Tag game. *Breach:* most directly relevant multi-agent GPU framework — its Tag benchmark mirrors 5–10-unit squads; "single mutable GPU state store, updated in place" is the template for surfacing resident state to a policy.

## 2. JAX RL-environment ecosystem (design patterns / self-play harnesses)
- **JaxMARL + SMAX** — Rutherford et al. 2023, arXiv:2311.10090; github.com/FLAIROX/JaxMARL. First broad MARL-in-JAX; ~14×, up to ~12,500× vmap'd; SMAX = JAX SMAC without SC2. *Breach:* SMAX is the closest published TASK to Breach; its self-play + CTDE harness and IPPO/MAPPO baselines are reusable reference designs.
- **PGX** — Koyamada et al. 2023, arXiv:2303.17503; github.com/sotetsuk/pgx. Board/game sims in JAX, 10–100×; AlphaZero example. *Breach:* template for GPU-resident game-tree self-play if Breach adds MCTS planning.
- **Gymnax** — Lange 2022; github.com/RobertTLange/gymnax. Env-as-pure-function API.
- **Jumanji** — Bonnet et al. 2023, arXiv:2306.09884; github.com/instadeepai/jumanji. Scalable combinatorial envs; state-carrying functional reset/step.
*Cross-cutting:* a stateless functional step over an explicit state struct vmaps trivially across thousands of envs. Breach's fixed-point state already IS such a struct — exposing `(state, action) → (state', obs, reward, done)` (even from C++) unlocks batch throughput.

## 3. Fast batched env execution (CPU-side, for contrast)
- **EnvPool** — Weng et al. (Sea AI Lab) NeurIPS 2022, arXiv:2206.10558; github.com/sail-sg/envpool. C++ threadpool async executor: 1M FPS Atari, 3M steps/s MuJoCo. *Breach:* **the bottleneck Breach gets to skip** — cite it to quantify the CPU baseline Breach beats.
- **PufferLib 2.0** — Suarez 2024, arXiv:2406.12905; RLC/RLJ 2025; puffer.ai. Vectorization + "emulation" making complex/multi-agent envs look simple; Ocean envs 100M+ SPS; **PuffeRL** (hardened fast PPO). *Breach:* realistic low-ceremony non-JAX training front-end; "make the env look like a flat batched tensor and PPO goes brrr."

## 4. Distributed / high-throughput architectures
- **A3C / A2C** — Mnih et al. 2016, arXiv:1602.01783. A2C's synchronous batched form is what a GPU-resident sim wants (all envs step in lockstep, one forward pass).
- **IMPALA + V-trace** — Espeholt et al. ICML 2018, arXiv:1802.01561. Decoupled actors + central learner; V-trace corrects off-policy lag; ~250k FPS. *Breach:* even on one GPU, if inference and learning run as separate CUDA streams, actors lag the learner — V-trace is the principled, cheap fix.
- **Ape-X** — Horgan et al. ICLR 2018, arXiv:1803.00933. Distributed prioritized replay. *Breach:* reference if going off-policy; multi-machine framing overkill for single-GPU residency.
- **R2D2** — Kapturowski et al. ICLR 2019, openreview r1lyTjAqYX. Ape-X + LSTM, stored recurrent state + burn-in. *Breach:* canonical recipe for recurrent policies off-policy (partial observability).
- **SEED RL** — Espeholt et al. ICLR 2020, arXiv:1910.06591; github.com/google-research/seed_rl. Inference ON the learner's accelerator (centralized batched inference); 40–80% cost reduction. *Breach — high:* SEED's central insight IS Breach's situation by construction; the architecture Breach gets "for free" — batch policy forward-passes across all envs into one kernel launch.
- **Sample Factory (APPO)** — Petrenko et al. ICML 2020, arXiv:2006.11751; samplefactory.dev. Async PPO tuned for a single machine; >10^5 FPS; supports self-play. *Breach — very high:* closest philosophical match (max FPS from one box); double-buffered sampling + APPO off-policy correction. Strong front-end candidate.
- **Podracer: Anakin & Sebulba** — Hessel et al. 2021, arXiv:2104.06272. Anakin (fully on-device, env pure JAX, 5M steps/s grid-worlds); Sebulba (decomposed actor-learner for CPU-side envs). Cleanba = GPU Sebulba. *Breach — high:* **Anakin pattern is Breach's ideal end-state** (env + agent compiled into one on-device program); Sebulba/Cleanba the fallback when the encoder must touch host.
- **Gorila** — Nair et al. 2015, arXiv:1507.04296. Historical ancestor; superseded by Ape-X.

## 5. Scale results & on-/off-policy tradeoff
- **OpenAI Five** — Berner et al. 2019, arXiv:1912.06680. Superhuman Dota 2 via massively-scaled PPO self-play (~2M frames every 2s), ~10 months, "surgery." *Breach:* existence proof that scaled on-policy self-play reaches superhuman team play; long-horizon handling + reward shaping reference.
- **AlphaStar** — Vinyals et al. Nature 2019 (s41586-019-1724-z). Grandmaster SC2 via league self-play; autoregressive self-attention + LSTM policy; 139M params, 32 TPUs, 44 days, seeded from human replays. *Breach — high:* definitive playbook for avoiding self-play collapse; league = recommended self-play scheme; autoregressive action head handles "actions for 5–10 units."
- **On- vs off-policy when the env is nearly free:** the classic calculus flips. PPO (on-policy) is sample-inefficient but trivially parallel/stable → wins wall-clock when data is cheap (why Isaac Gym/Brax/OpenAI Five use it). But:
  - **Parallel Q-Learning (PQL)** — Li et al. (MIT Improbable AI) ICML 2023, arXiv:2307.12983; github.com/Improbable-AI/pql. Purpose-built for massively-parallel GPU sim; parallelizes data collection + policy + value learning as separate workers on one workstation; **beats PPO in both wall-clock and sample efficiency** on 6 tasks. *Breach:* the modern answer to "on- or off-policy for a GPU-resident sim" — start on-policy for simplicity, keep PQL as the upgrade lever.

**Takeaway:** because the sim is cheap and resident, **begin on-policy (PPO/APPO)** — simplest, stablest, proven at team-game scale. Keep off-policy (PQL / R2D2) as a deliberate second-phase sample-efficiency lever.

## 6. Determinism & reproducibility — Breach's under-appreciated edge
- **Deterministic Implementations for Reproducibility in Deep RL** — Nagarajan et al. 2018/2019, arXiv:1809.05676. Three nondeterminism sources: GPU nondeterminism (non-associative float reductions, arch-specific kernels), random exploration, random init — each alone can swing performance, demanding many-seed averaging.
- **Deep RL that Matters** — Henderson et al. 2018, arXiv:1709.06560. Canonical warning on variance/seed-hacking.
- *Breach — the structural advantage:* the literature treats the ENVIRONMENT as one more noise source; Breach removes it entirely (Q16.16, bit-identical). Concretely: (1) **distributed self-play without divergence** — shared-seed actors on different machines produce identical trajectories; no silent drift between a learner's replay and the actor (a real float-sim bug source); V-trace then corrects only for POLICY lag. (2) **Perfect replay & debugging** — any trajectory reproducible bit-for-bit from (seed, actions); the CPU reference build is an exact oracle. (3) **Trustworthy evaluation** — eval variance collapses to policy stochasticity + init/GPU-net noise; fewer seeds; fair league match-ups. (4) **Caution:** sim-determinism ≠ training-determinism (cuDNN/atomics, async timing still inject noise) — set `torch.use_deterministic_algorithms(True)` + seed everything for fully reproducible RUNS (modest throughput cost), else keep sim-determinism (needed) and treat net-nondeterminism as ordinary seed variance.

## 7. Decision cadence / temporal abstraction — "act every N ticks?"
Frame-skip / action-repeat / action-persistence is one of the most consequential and cheapest knobs.
- **Frame Skip Is a Powerful Parameter** — Braylan et al. 2015. Often matters more than algorithmic choices; Atari uses skip=4. Repeating an action k times (a) cuts effective horizon by k (easing credit assignment + effective discount), (b) speeds wall-clock, (c) aids exploration. Too high → can't react; too low → horizon explodes.
- **Control frequency shapes the whole problem** — Faster RL by Freezing Slow States arXiv:2301.00922; Managing Temporal Resolution in Continuous Value Estimation arXiv:2212.08949 (resolution/variance trade-off); Sequence RL arXiv:2410.08979 (act well at lower decision frequencies via action sequences).
- **Learned/adaptive cadence:**
  - **Options / semi-MDPs** — Sutton, Precup & Singh AIJ 1999. Temporally-extended options over an MDP form a semi-MDP; mix with primitives. Theory under everything below.
  - **FiGAR** — Sharma et al. ICLR 2017, arXiv:1702.06054. Factorizes policy into *what action* × *how long to repeat*; drops into A3C/TRPO/DDPG.
  - **Dynamic Frame-skip DQN** — Lakshminarayanan et al. 2016, arXiv:1605.05365. Repeat count as a learnable discrete choice.
  - **TempoRL** — Biedenkapp et al. ICML 2021, arXiv:2106.05262. Learns a skip-policy ("commit for j steps"); up to ~10× faster learning.
  - **Action persistence / PFQI** — Metelli et al. ICML 2020, arXiv:2002.06836. Persistence as a control-frequency operator with convergence guarantees.
- *Breach — concrete guidance:* (1) **Do not act every tick.** At 12–24 Hz a tick is ~40–80 ms; commit to actions for **~3–6 ticks (≈150–300 ms)** → near a human reaction budget, ~quarters the horizon (helps credit assignment, keeps discount lower), ~quarters expensive forward-passes. (2) **Start with a fixed skip (~4)**, sweep it early (highest-leverage single knob). (3) Then consider a learned cadence (FiGAR head / TempoRL skip-policy) — units idle cheaply, react fast at contact. (4) Frame as options/semi-MDPs so value targets stay correct under variable action duration.

## 8. State encoding on GPU (Breach's planned CUDA encoder)
No single canonical paper, but established practice in the simulators above: Isaac Gym writes obs buffers from PhysX tensors; GPUDrive/Madrona write obs/reward in C++/CUDA handing Python device pointers; WarpDrive keeps one in-place GPU store. Recipe:
1. Encoder = CUDA kernel reading the resident fixed-point state, writing a contiguous `[num_envs, num_agents, obs_dim]` float/half tensor **in place**, never copying to host.
2. Hand it to the policy as a zero-copy tensor — **`__cuda_array_interface__` / DLPack** bridges CuPy↔PyTorch↔JAX without memcpy. **Single most important integration detail** — no device→host→device bounce.
3. Convert Q16.16 → float (or bf16) INSIDE the kernel; normalize there. Keep sim state fixed-point (determinism), let observations be float (the net doesn't need bit-identity — only the sim does).

## Recommended stack for Breach (ranked, concrete)
Guiding principle: exploit residency and determinism; don't scale out before saturating one GPU.
1. **Keep the whole loop on the GPU (non-negotiable).** Sim → CUDA encoder → inference → sampling → sim, all device-resident, tensors shared zero-copy via DLPack. SEED/Anakin/Isaac pattern. **Build the CUDA state-encoder + zero-copy hand-off as milestone one.**
2. **Algorithm: start on-policy PPO, single-machine async (APPO).** Batch policy forward-passes across all concurrent games into one kernel launch (SEED-style, free for Breach). Prototype with **PufferLib/PuffeRL** or **Sample Factory (APPO)** — single-box, high-FPS, self-play-capable, PyTorch-native (marries a CuPy/CUDA sim without a JAX rewrite). rl_games/skrl equally valid if the tensor API is Isaac-shaped.
3. **Decision cadence: act every ~4 ticks (fixed skip), sweep it.** Phase two: learned cadence (FiGAR/TempoRL); model as semi-MDP/options.
4. **Multi-unit actions: autoregressive action head (AlphaStar-style)** + self-attention over units.
5. **Self-play: league-based (AlphaStar), not naive.** Main agents + exploiters; determinism makes match-ups fair + reproducible.
6. **Partial observability: recurrent policy (LSTM/GRU) with R2D2-style stored-state replay** if/when off-policy; until then frame-stacking + recurrent core on-policy.
7. **Second-phase sample-efficiency lever: Parallel Q-Learning (PQL)** if PPO's sample cost bites.
8. **Keep a bit-identical CPU reference build (Madrona-style)** as an exact determinism/divergence oracle.
9. **Defer multi-GPU/multi-node** (IMPALA/Ape-X/Sebulba) until one GPU is saturated; determinism means actors never diverge — add V-trace for policy staleness. Cleanba if JAX; Sample Factory already multi-GPU on one box.

## Key open problems / cautions
- **Encoder + hand-off is make-or-break** — if the obs tensor bounces to host, residency gains evaporate; verify zero `cudaMemcpy DtoH` in the hot loop with a profiler.
- **Sim-determinism ≠ training-determinism** — decide deliberately: fully reproducible runs (deterministic cuDNN, some throughput cost) vs reproducible environments (what you need) + ordinary net seed variance.
- **On- vs off-policy genuinely contested under cheap sim** — A/B once the pipeline is stable; don't over-commit.
- **Frame-skip interacts with everything** (discount, exploration, shaping, horizon) — tune jointly, re-tune after reward changes.
- **Self-play instability** (collapse, cycling, forgetting) — league is a mitigation, not a cure.
- **Low tick rate (12–24 Hz) cuts both ways** — cheap + short horizons, but caps skill ceiling if sub-tick reactions are needed (Sequence-RL / slow-decision-frequency literature).
- **Uncertainty:** first-party FPS = order-of-magnitude; Madrona arXiv ID unconfirmed (cite via project site / SIGGRAPH 2023).
