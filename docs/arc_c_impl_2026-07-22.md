## C0 — recon + panes shell

### As-is note (current map_editor.py architecture, mapped at C0)

`tools/map_editor.py` (~1.7k lines) is a single pyray (raylib) tool. All pure
geometry/writeback helpers live at module scope + in `tools/level_edit_common.py`
(palette, brush, `line_tiles`, `paint_tiles`, CSV save, `UndoRing`,
`art_px_to_tile`); the interactive part is ONE big function `run_editor()`
holding all state as locals + one `while not rl.window_should_close()` loop.
raylib has no input-injection API, so the loop is smoke-tested via `--auto`
(renders ~90 frames, cycles view modes, screenshots, exits) and the pure
helpers carry the unit tests (`tests/test_map_editor_tool.py`).

- **Main loop** (per frame): read modifier/mouse state → global keys
  (quit/mode/view/palette) → view (wheel-zoom / WASD+MMB pan) → cursor-tile
  resolve → per-mode input branch → undo/save → draw (world then HUD) →
  `--auto` plumbing.
- **MODES** = `("PAINT","ROOM","CORRIDOR","DOOR","SPAWN","LIGHT","WATER")`.
  Mode state is a single int `mode_idx`; `mode = MODES[mode_idx]`. TAB/Shift+TAB
  cycles, F1..F7 jumps. `cancel_transients()` drops drag/stroke state on every
  switch.
- **Input dispatch**: one big `if mode == "PAINT": … elif "ROOM": …` chain.
  Each branch reads `lmb/rmb/lmb_click/rmb_click/lmb_up` + mode keys. The
  `over_hud = mouse.y <= HUD_H` gate blocked edits when the cursor was over the
  top HUD strip; every editing branch is guarded by `not over_hud`.
- **Draw loop**: `to_screen(wx,wy) = ((wx-cam)*zoom)` full-window; baked
  texture (or material-colour fallback) → grid lines → mode cursor overlays →
  water overlay → spawn markers → light markers → HUD. View transform is
  `screen = (world_px - cam) * zoom`; `art_px_to_tile` is the inverse for the
  cursor. Preview is a live baked GPU texture (`bake_full` once, `bake_region`
  dirty-rect re-bakes, +1-tile margin for the edge16 neighbour contract).
- **Toolbar/HUD/status**: drawn as ONE opaque strip `rl.draw_rectangle(0,0,
  win_w,HUD_H)` at frame end — five text lines (level/grid/zoom/view; mode +
  material + per-mode extra; palette chips + undo depth; mode hint; global
  keybind help) + a transient `flash`/`flash_frames` status line below it.
- **level_lib usage (read+write, the single data layer)**: opens via
  `level_lib.open_level()` → `handle.data` (tilemap, spawns, lights,
  water_depth_q, raw_toml). Refuses v≠2 and no-`[bake]` (painted) levels.
  SAVE (Ctrl+S): `save_tilemap_csv` (own .bak) → `mask_water_to_open` guard →
  `level_lib.write_water_npy` → `handle.save({...spawn/light/water managed
  blocks...})` (ONE atomic temp+rename, one session .bak) → `bake_level`
  (rewrites `[art]`/`[bake]`, `write_bak=False`) → `handle.record_disk_state`.
- **Per-domain undo rings (C2 REPLACES these with a transaction log)**:
  1. `undo` = `UndoRing` (numpy grid snapshots) — shared by PAINT/ROOM/
     CORRIDOR/DOOR tile mutations.
  2. `spawn_undo` = `SpawnRing` (dataclass-list snapshots) — SPAWN only.
  3. `light_undo` = `SpawnRing` — LIGHT only.
  4. `water_undo` = `UndoRing` (numpy depth-grid snapshots) — WATER only.
  Ctrl+Z pops the ring for the CURRENT mode (spawn/light/water in their modes,
  else the tile ring). Rings are deliberately separate today so Ctrl+Z in one
  domain can't silently rewind another. Push points are scattered through each
  mode branch (before each mutating action / before each drag commit).
- **Global mutable state a panes refactor must respect**: `grid` (numpy,
  mutated in place + snapshotted for undo; the live baked textures
  `tex_diffuse`/`tex_normal` are kept in sync by `rebake_*`); `spawns`/`lights`
  (dataclass lists), `water_q` (int32 Q16.16 grid); the four `dirty_*` flags +
  their `*_bak_written` once-per-session guards; camera (`cam_x/cam_y/zoom`);
  stroke/drag transients (`stroke_active/pending/dirty`, `room_start`,
  `corr_start`, `spawn_drag`, `light_drag`, `anchor_tile`, `last_paint_tile`);
  `flash/flash_frames`, `esc_armed`. `preview_ppt` may differ from bake ppt
  (texture-cap divisor). All of this lives as `run_editor` locals — there is no
  editor object; a panes refactor works within that function.

### Impl note (as-built C0 — panes shell)

**New module `tools/editor_layout.py`** — the pure pane-layout abstraction (no
raylib import, fully headless-testable):
- `Rect(x,y,w,h)` with half-open `contains()` (adjacent panes never both claim
  a pixel).
- `compute_panes(win_w, win_h) -> {top_bar, tool_rail, canvas, palette,
  inspector, status_bar}`. The canvas is derived by subtraction so the six
  rects **tile the window exactly** (no overlap, no gaps) at any size; every
  dim is clamped ≥ 0 so a sub-chrome window still tiles. Layout: top bar (full
  width) · left tool rail · centre canvas · right column split palette(top)/
  inspector(bottom) · status bar (full width).
- `pane_at()` (canvas-first hit test), `screen_from_world`/`world_from_screen`
  (canvas viewport transform = old `(world-cam)*zoom` shifted by the canvas
  pane origin; exact inverses), `fit_camera` (centre world in the canvas).

**`tools/map_editor.py` rehosted onto the shell — zero editing-behavior change**:
- Camera now fits the world into the **canvas pane** (`fit_camera`) instead of
  the full window; `panes`/`canvas` recomputed each frame from the live window
  size (still resizable).
- `over_hud` kept its meaning but is now `= not over_canvas` (mouse over any
  non-canvas pane) — so all 14 `not over_hud` edit-gates are unchanged in
  semantics; canvas clicks still edit, chrome clicks don't.
- Cursor-tile, wheel-zoom and `to_screen` are **canvas-relative** (mouse offset
  by the canvas origin). Wheel-zoom is now gated to the canvas (scrolling over
  a pane no longer zooms; also avoids zooming around an off-canvas point).
- The world draw is wrapped in `begin/end_scissor_mode(canvas)` so the map
  clips to its pane; the old single HUD strip is replaced by five framed panes
  drawing the **same information** (top bar: level/grid/zoom/view; tool rail:
  the mode list, active row highlighted; palette: chips+names, selected boxed;
  inspector: `[MODE]` + material + per-mode extra + wrapped hint + undo depth;
  status bar: **mode · cursor tile · validator summary(flash) · unsaved dot ·
  registry-import banner slot** — the banner slot is empty in C0, C1 fills it).
- Pane click-routing added (mirrors existing keys, removes nothing): tool-rail
  row → select mode (= TAB/F1–F7); palette chip → select material (= 0–9).
  Row geometry constants (`RAIL_*`, `PAL_*`) are shared by hit-test and draw.
- Removed `HUD_H`/`COL_HUD_BG`; added pane colours + `editor_layout` import.

**Verification**: `--auto` on `bake_demo` ran all 90 frames through the new
draw path (view-mode cycling included) and screenshotted a correct 6-pane
layout with the map cleanly clipped to the canvas (no bleed into chrome).

**Test `tests/test_editor_layout.py`** (headless, 15 cases): panes tile the
window exactly (no overlap / no gaps, areas sum to W·H) across 9 sizes incl.
sub-chrome; default-size adjacency; half-open `contains`; `pane_at` canvas
priority; canvas transform invertibility; **tile→screen→tile round-trip in the
canvas pane**; `fit_camera` centring. `run_editor` itself needs a real GL
context + a baked level (not headlessly constructible), so per the gate its
plumbing stays on `--auto` + these pure helpers.

**Gate**: full suite `pytest tests -q` = **1176 passed, 22 skipped, 1 warning**
(warning pre-exists: an intentional zone authoring-warning in test_zones). Zero
goldens/digests touched (entity-digest, b6-logic-golden, unit-state-digest all
green). NOTE: this fresh worktree had no compiled `breach_physics` — built once
via `cpp/build_cpu_data.bat` (CPU, in-bounds: compile only, no cpp/golden
edits) so the sim tests collect; the `.pyd` is gitignored build output.

**For C1**: the registry-driven palette + inspector replace the `palette` and
`inspector` panes — geometry is already carved (`panes["palette"]`,
`panes["inspector"]`); reuse `PAL_PAD_Y`/`PAL_ROW_H` or replace them. The
status bar already reserves the **registry-import banner slot** (draw it at the
right of `status_bar`, left of the unsaved tag). SPAWN/LIGHT are still the
bespoke dataclass paths (untouched by C0) — C1 ports them onto `[[entity]]` and
deletes the bespoke paths; the four undo rings stay until C2's transaction log.

## C1 — registry palette + inspector

### Registry load + fallback (canon §1)

New module `tools/entity_editor_ui.py` (no raylib import, headless-testable):
`load_registry()` calls `import simulation.entities` then
`export_registry_json()` (rewrites `entity_registry.json`, repo root,
gitignored, as the new last-good — canon §1: "rewritten on every successful
launch") and returns `registry_payload()`. On ANY import-time exception it
falls back to reading the last-good `entity_registry.json` and reports
`ok=False` + the error string; the palette still renders from whatever the
last-good snapshot carried. Both failing (fallback file also unreadable) is
a loud `RuntimeError` — the one case the editor can't start from. An
`importer=` seam lets tests simulate an import failure without breaking a
real class; the semantics it exercises (escalation trigger 4) are
unchanged from canon §1 — only the test injection point is new.

Deliberately does **not** import anything from `simulation.entities` at
module scope (not even the `KIND_*` schema constants — schema.py's closed
vocabulary is duplicated as plain string literals instead): if the live
import is what's broken, this module — palette + inspector included — must
still work purely off the JSON fallback payload.

`map_editor.run_editor` calls `load_registry()` once at launch (no args —
the real repo-root file both ways); `registry_banner` is set from
`registry_result.error` and drawn in the status bar's reserved slot (red,
right of the validator/flash text, left of the `UNSAVED *` tag) whenever
`not registry_result.ok`.

### Registry-driven palette (tabbed)

The palette pane is now genuinely tabbed: **MATERIAL** (unchanged C0
content) and **ENTITY** (new), click-switchable at a small header row drawn
at the top of the pane (`PAL_TABS`, hit-tested by `rl.measure_text` so the
click target matches the draw exactly). `entity_editor_ui.palette_entries()`
returns one `PaletteEntry` (class name, class-initial glyph, a deterministic
generated colour chip — same golden-angle hue-walk recipe as
`level_edit_common._auto_rgb`, keyed by a hash of the class NAME since
entity classes have no small integer id) per class in the loaded registry
payload, **sorted by name**.

Scope call: the schema has no "placeable" flag — `INTANGIBLE` means "no
tile", not "not an instance" — so every registered class gets a palette
entry, not just the kickoff doc's four named examples (`door`, `light`,
`breach_site`, `extraction_zone`). The real registry today also surfaces
Arc B's logic/sensor/actuator/control classes (`decider`, `gate_and/or/not`,
`filter`, the six field/motion/clock sensors, `airlock_controller`,
`button`, `terminal`) this way. C1 only needs selection + a template
display to work (task spec); C3+ decide which classes get a dedicated
placement gesture vs the generic place-one, and can filter the palette
further then if that turns out to matter. Clicking a chip sets
`selected_entity_class`, which the inspector reads.

### Registry-driven inspector

`entity_editor_ui.inspector_rows(cls_payload, values)` renders one
`InspectorField` per declared schema field (schema order, not sorted): a
kind-aware `display` string (`format_field_value`) plus `editable` +
min/max/choices for a future widget. `KIND_LENGTH_M` fields show
`"{meters} m -> {tiles} tiles"` via `quantize_length_m` — the editor doc §4
exact rule, `floor(length_m * tiles_per_m + 1/2)` in `Fraction` arithmetic
(round-half-up, base `tiles_per_m = 3`), cross-checked in tests against
`simulation.entities.door.quantize_span_tiles` for the same inputs.

**Editable kinds in C1**: `int`, `q16`, `length_m`, `bool`, `enum`,
`float_render`, `color_rgb`. **Display-only**: `str`, `str_list`, `roster`,
`entity_ref` — map_editor.py has never had in-UI text input ("No in-UI
text input in v1" is its own standing rule; ids are auto-minted, never
retyped), and tag/roster assignment is explicitly later arcs' job (C4 tags,
C5 zone roster). No generic edit WIDGET ships in C1 either way: the only
class with live instances to edit is `light` (LIGHT mode, below), and its
existing bespoke keys already satisfy "editing a field updates the
instance" — building a second, generic editing path for zero other classes
(nothing else has a placement tool yet) would be speculative work with no
oracle. The inspector shows two things depending on state, first match
wins: (1) LIGHT mode with a light hovered → that instance's live fields
(`light_entity_port.light_entry_to_fields`); (2) an ENTITY-tab class
selected → that class's default template (`values={}`, so every field
reads its registry default); else the unchanged C0 mode/material/hint
content.

### The LIGHT port (Amendment A1) — bespoke path deleted, parity proven

New module `tools/light_entity_port.py`. `light.py`'s schema mirrors
`LightEntry` field-for-field **by design** (its own docstring says so), so
the port keeps every existing LIGHT-mode interactive line in
`map_editor.py` (B/C/R/E/P/X/H keys, drag, hover hit-test, the whole
~100-line block) **completely unchanged** — only the LOAD and SAVE
boundaries move:

- `EditableLight(LightEntry)` adds the one new fact a `[[entity]]` instance
  is mandatory to carry: `id`. It's a dataclass **subclass**, not a change
  to `level_loader.LightEntry` (out of the allowed surface anyway) — so
  every existing `dataclasses.replace(lights[i], ...)` call keeps working:
  `replace()` preserves the subclass and every field, `id` included,
  across every edit (verified directly, not just inferred).
- **`light_form(raw_toml)`** decides ONCE at load, from raw TOML alone:
  `"legacy"` when the file has any raw `[[light]]` block, `"entity"`
  otherwise — including a level with **zero** lights, since the bespoke
  `[[light]]` WRITER no longer exists to fall back to. This is not a
  migration: nothing legacy gets converted, because there is nothing
  legacy to convert.
- **`initial_editable_lights(lvl)`** seeds ids at load: entity-form levels
  keep their authored `[[entity]]` ids (`lvl.lights[i]` <-> the i-th
  `class == "light"` entity, in file order — level_loader's own
  construction order, and mixed forms hard-error so the two cases never
  interleave); legacy levels mint fresh `light_N` ids (nothing references a
  legacy light by id, so a fresh mint costs nothing).
- **`merge_light_entities(original_entities, lights)`** rebuilds the
  `[[entity]]` array for a save: pre-existing non-light entities (doors,
  zones — nothing edits those yet) keep their exact file position; each
  pre-existing light's slot is replaced by its current edited form or
  dropped if deleted; brand-new lights append at the end. This bounds a
  save's file-order churn to "what changed" — reshuffling would not be a
  correctness bug (canon §2: refs address ids, never positions) but would
  needlessly perturb the ENTITY_SECT_V1 digest row order for anyone who
  opens a mixed door+light level and saves.
- **`format_lights_for_save(light_form, lights, other_entities)`** is the
  one function `map_editor.py`'s Ctrl+S calls: returns `{"light": ...}` or
  `{"entity": ...}`, **never both**, never the family the level did NOT
  already use — the untouched family is simply omitted from
  `level_lib`'s `replacements` dict, and `level_lib` already preserves
  omitted families byte-for-byte (existing, tested behavior — no
  escalation needed, confirmed by `test_legacy_level_save_stays_legacy_form_no_entity_family`).

**Parity proof** (escalation trigger 5 — a bespoke-path DELETE can't reach
behavior-parity first): `tests/test_light_entity_port.py::
test_editor_authored_light_matches_legacy_authoring` builds one
`LightEntry` (static and beacon cases), writes it into a level TWO ways —
via legacy `format_light_lines` and via THIS port's
`merge_light_entities`/`light_to_entity_instance` + `format_entity_lines`
— reloads both through `level_loader.load`, and asserts the resulting
`LightEntry` values are dataclass-equal. This exercises the EDITOR's new
authoring code specifically (not just level_loader's pre-existing
`_light_entry_from_entity` alias contract, which `test_entity_format.py`
already covers).

**Known gap for C2**: `light_undo` (the bespoke `SpawnRing`) still holds
`EditableLight` snapshots exactly as before — it works today (verified:
`dataclasses.replace` + `SpawnRing.push`/`pop` are fully generic over any
dataclass) but per Arc C1's own scope it is NOT ported into a transaction
log; that's explicitly C2's job for every domain's ring, LIGHT included.

### Module layout

**New `tools/undo_log.py`** — pure, headless, no raylib import:
- `UndoContext(grids, collections)` — the live-state registry. `grids` maps a
  name to the numpy array (written in place via fancy indexing), `collections`
  maps a name to the dataclass list (written via slice-assign). Handles are
  refilled in place for the whole session, never rebound (§7).
- `GridCellsOp(grid_name, ys, xs, before, after)` — a delta on one grid
  (changed cells only). `undo/redo` = `grid[ys, xs] = before/after`;
  `bounding_rect()` (a re-bake HINT only); `nbytes` = the four arrays'
  (~16 B/cell).
- `CollectionOp(coll_name, before, after)` — a whole-list snapshot pair.
  `before`/`after` are `copy.deepcopy` lists (B1); `undo/redo` slice-assign a
  FRESH deep copy so the live list never shares mutable substructure
  (`EntityInstance.fields`/`.tags`) with the retained snapshot.
- `Transaction(label, ops)` — apply in order / invert in reverse order (§1.2);
  `rebake_rects()` yields `(grid_name, rect)` for its grid ops.
- `TransactionLog(ctx, depth=256, max_bytes=128 MB)` — the linear cursor + redo
  truncation + saved-marker dirty + front-eviction + the builder seam. Bounds
  are constructor args (C7) so tests pass a tiny ceiling.

**`tools/light_entity_port.py`** — added `unique_entity_id(prefix,
*collections)`, the B3 union id allocator scanning `lights ∪ entities ∪ …`
(kept `unique_light_id` — tests + `initial_editable_lights` still use it).

### The builder seam integration

Immediate-mode capture (§2.1): every gesture calls `log.begin(label)` +
`log.snapshot_grid(name)`/`log.snapshot_coll(name)` at its START, mutates live
state EXACTLY as before (the ~1.7k-line loop's mutation code is unchanged), and
`log.commit()` at its END extracts the delta vs the now-mutated state and
pushes ONE transaction (or drops it if empty). Grid ops use a **whole-grid**
`before != live` diff (B2 — never bounded by a gesture rect); per-gesture rects
(`stroke_dirty`) survive only as the live-preview re-bake hint. `commit()` is
the only log-mutation point. `cancel_transients()` (mode switch / Esc) commits
any open transaction — a no-op gesture drops, a real change is kept (the
blessed drag-commit-on-interrupt improvement, §2.4). `abort()` (reverts from
the retained before-copy) is on the surface for C4 but no C2 editor path needs
it (validation precedes every live mutation).

### The four-ring migration (17 push-points)

`UndoRing`/`SpawnRing`/`light_undo`/`water_undo` + the four `dirty_*` bools are
GONE from `map_editor.py`. **`UndoRing` STAYS** in `level_edit_common.py`
(shared by `align_level_art.py` + `test_level_water.py` +
`test_map_editor_tool.py`); C2 only stopped `map_editor.py` instantiating it.
**Only the map-editor-local `SpawnRing` class was deleted.** All 17 push-points
became `begin/snapshot/commit`:

| domain | push-points → migration |
|---|---|
| PAINT | line-tool click, freehand stroke (start→`begin`+`snapshot_grid`, mouse-up→`commit`, coalesced) → `GridCellsOp("material")` |
| ROOM / CORRIDOR / DOOR | one `begin/snapshot/commit` per gesture → `GridCellsOp("material")` |
| SPAWN | team-toggle, place, drag-move (begin at mouse-down, commit at release — drops if unmoved), delete → `CollectionOp("spawns")` |
| LIGHT | kind (B), colour (C), R/E/P/X nudge, phase (H), place, drag-move, delete → `CollectionOp("lights")` |
| WATER | fill / drain → `GridCellsOp("water")` |

`ctx.grids = {"material": grid, "water": water_q}`;
`ctx.collections = {"spawns": spawns, "lights": lights, "entities": entities}`
— constructed once, the SAME objects the loop closes over and Ctrl+S
serializes. `other_entities` was renamed `entities` and pinned as
`ctx.collections["entities"]` (B4 — the object `format_lights_for_save`
writes); light id minting routes through `unique_entity_id("light", lights,
entities)` (B3). The mode-scoped Ctrl+Z dispatch collapsed to one global
`log.undo()`; redo added (`Ctrl+Y` / `Ctrl+Shift+Z`, explicit shift guard, C9).
All SIX dirty consumers (§7.1) rewired to `log.dirty` / `log.mark_saved()` /
`undo N / redo M` — including the end-of-session PRINT that would NameError.
Save-time `mask_water_to_open` is wrapped as a committed `GridCellsOp("water")`
BEFORE `log.mark_saved()` (C1); a code comment flags that this mask-commit
truncating the redo tail is intended.

### What C3+ must do to register their ops (the extension pattern)

Reuse a primitive with a registered name; add a new grid/collection to the ctx
registry only for a genuinely new array/list. No third op type is needed.

- **C3 DOOR placement** = ONE transaction carrying BOTH a
  `GridCellsOp("material")` (stamp `MAT_DOOR_CLOSED`, id 7) AND a
  `CollectionOp("entities")` (the door entity) — the compound archetype
  (`test_compound_transaction_atomic_grid_plus_entity` pins it). Build it
  between one `begin("door")` and one `commit()`: `snapshot_grid("material")`,
  `snapshot_coll("entities")`, stamp + append, commit. Mint the door id via
  `unique_entity_id("door", lights, entities)` (B3).
- **C3 sensor / generic place-one** = `CollectionOp("entities")` only (no grid
  stamp); mint via `unique_entity_id`. Validate (solid-`sample_tile` refusal)
  BEFORE the first mutation, so a refused placement never opens a transaction.
- **C4 multi-select move / tag / clump-paste** = `CollectionOp("entities")`
  (+ `CollectionOp("wires")` once `wires` is registered) — the whole-list
  snapshot handles re-id + N-at-once for free. An id-changing op MUST carry the
  `wires`/tag `CollectionOp`s in the SAME transaction (§7 referential rule).
- **C5 zone/air paint** = `GridCellsOp("zones")`/`GridCellsOp("air")` — register
  those grids in `ctx.grids` only once allocated (they are `None` at load; a
  `GridCellsOp` on `None` would fail). A tool that resizes/crops a grid
  invalidates stored coordinates → it must reset the log (no Arc C tool does).
- **C6 wire add/remove** = `CollectionOp("wires")` after registering the
  `wires` collection in `ctx.collections`.

Constraint on any future op type (§6.3): store-and-assign only — never derive
its effect from state a sibling op in the same transaction writes, or
reverse-order inversion breaks.
