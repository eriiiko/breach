## C0 — recon + panes shell

### As-is note (current map_editor.py architecture, mapped at C0)

`tools/map_editor.py` (~1.7k lines) is a single pyray (raylib) tool. All pure
geometry/writeback helpers live at module scope + in `tools/level_edit_common.py`
(palette, brush, `line_tiles`, `paint_tiles`, CSV save, `UndoRing`,
`art_px_to_tile`); the interactive part is ONE big function `run_editor()`
holding all state as locals + one `while not rl.window_should_close()` loop.
raylib has no input-injection API, so the loop is smoke-tested via `--auto`
(renders ~90 frames, cycles view modes, screenshots, exits) and the pure
helpers carry the unit tests (`tests/test_map_editor_tool.py`).

- **Main loop** (per frame): read modifier/mouse state → global keys
  (quit/mode/view/palette) → view (wheel-zoom / WASD+MMB pan) → cursor-tile
  resolve → per-mode input branch → undo/save → draw (world then HUD) →
  `--auto` plumbing.
- **MODES** = `("PAINT","ROOM","CORRIDOR","DOOR","SPAWN","LIGHT","WATER")`.
  Mode state is a single int `mode_idx`; `mode = MODES[mode_idx]`. TAB/Shift+TAB
  cycles, F1..F7 jumps. `cancel_transients()` drops drag/stroke state on every
  switch.
- **Input dispatch**: one big `if mode == "PAINT": … elif "ROOM": …` chain.
  Each branch reads `lmb/rmb/lmb_click/rmb_click/lmb_up` + mode keys. The
  `over_hud = mouse.y <= HUD_H` gate blocked edits when the cursor was over the
  top HUD strip; every editing branch is guarded by `not over_hud`.
- **Draw loop**: `to_screen(wx,wy) = ((wx-cam)*zoom)` full-window; baked
  texture (or material-colour fallback) → grid lines → mode cursor overlays →
  water overlay → spawn markers → light markers → HUD. View transform is
  `screen = (world_px - cam) * zoom`; `art_px_to_tile` is the inverse for the
  cursor. Preview is a live baked GPU texture (`bake_full` once, `bake_region`
  dirty-rect re-bakes, +1-tile margin for the edge16 neighbour contract).
- **Toolbar/HUD/status**: drawn as ONE opaque strip `rl.draw_rectangle(0,0,
  win_w,HUD_H)` at frame end — five text lines (level/grid/zoom/view; mode +
  material + per-mode extra; palette chips + undo depth; mode hint; global
  keybind help) + a transient `flash`/`flash_frames` status line below it.
- **level_lib usage (read+write, the single data layer)**: opens via
  `level_lib.open_level()` → `handle.data` (tilemap, spawns, lights,
  water_depth_q, raw_toml). Refuses v≠2 and no-`[bake]` (painted) levels.
  SAVE (Ctrl+S): `save_tilemap_csv` (own .bak) → `mask_water_to_open` guard →
  `level_lib.write_water_npy` → `handle.save({...spawn/light/water managed
  blocks...})` (ONE atomic temp+rename, one session .bak) → `bake_level`
  (rewrites `[art]`/`[bake]`, `write_bak=False`) → `handle.record_disk_state`.
- **Per-domain undo rings (C2 REPLACES these with a transaction log)**:
  1. `undo` = `UndoRing` (numpy grid snapshots) — shared by PAINT/ROOM/
     CORRIDOR/DOOR tile mutations.
  2. `spawn_undo` = `SpawnRing` (dataclass-list snapshots) — SPAWN only.
  3. `light_undo` = `SpawnRing` — LIGHT only.
  4. `water_undo` = `UndoRing` (numpy depth-grid snapshots) — WATER only.
  Ctrl+Z pops the ring for the CURRENT mode (spawn/light/water in their modes,
  else the tile ring). Rings are deliberately separate today so Ctrl+Z in one
  domain can't silently rewind another. Push points are scattered through each
  mode branch (before each mutating action / before each drag commit).
- **Global mutable state a panes refactor must respect**: `grid` (numpy,
  mutated in place + snapshotted for undo; the live baked textures
  `tex_diffuse`/`tex_normal` are kept in sync by `rebake_*`); `spawns`/`lights`
  (dataclass lists), `water_q` (int32 Q16.16 grid); the four `dirty_*` flags +
  their `*_bak_written` once-per-session guards; camera (`cam_x/cam_y/zoom`);
  stroke/drag transients (`stroke_active/pending/dirty`, `room_start`,
  `corr_start`, `spawn_drag`, `light_drag`, `anchor_tile`, `last_paint_tile`);
  `flash/flash_frames`, `esc_armed`. `preview_ppt` may differ from bake ppt
  (texture-cap divisor). All of this lives as `run_editor` locals — there is no
  editor object; a panes refactor works within that function.

### Impl note (as-built C0 — panes shell)

**New module `tools/editor_layout.py`** — the pure pane-layout abstraction (no
raylib import, fully headless-testable):
- `Rect(x,y,w,h)` with half-open `contains()` (adjacent panes never both claim
  a pixel).
- `compute_panes(win_w, win_h) -> {top_bar, tool_rail, canvas, palette,
  inspector, status_bar}`. The canvas is derived by subtraction so the six
  rects **tile the window exactly** (no overlap, no gaps) at any size; every
  dim is clamped ≥ 0 so a sub-chrome window still tiles. Layout: top bar (full
  width) · left tool rail · centre canvas · right column split palette(top)/
  inspector(bottom) · status bar (full width).
- `pane_at()` (canvas-first hit test), `screen_from_world`/`world_from_screen`
  (canvas viewport transform = old `(world-cam)*zoom` shifted by the canvas
  pane origin; exact inverses), `fit_camera` (centre world in the canvas).

**`tools/map_editor.py` rehosted onto the shell — zero editing-behavior change**:
- Camera now fits the world into the **canvas pane** (`fit_camera`) instead of
  the full window; `panes`/`canvas` recomputed each frame from the live window
  size (still resizable).
- `over_hud` kept its meaning but is now `= not over_canvas` (mouse over any
  non-canvas pane) — so all 14 `not over_hud` edit-gates are unchanged in
  semantics; canvas clicks still edit, chrome clicks don't.
- Cursor-tile, wheel-zoom and `to_screen` are **canvas-relative** (mouse offset
  by the canvas origin). Wheel-zoom is now gated to the canvas (scrolling over
  a pane no longer zooms; also avoids zooming around an off-canvas point).
- The world draw is wrapped in `begin/end_scissor_mode(canvas)` so the map
  clips to its pane; the old single HUD strip is replaced by five framed panes
  drawing the **same information** (top bar: level/grid/zoom/view; tool rail:
  the mode list, active row highlighted; palette: chips+names, selected boxed;
  inspector: `[MODE]` + material + per-mode extra + wrapped hint + undo depth;
  status bar: **mode · cursor tile · validator summary(flash) · unsaved dot ·
  registry-import banner slot** — the banner slot is empty in C0, C1 fills it).
- Pane click-routing added (mirrors existing keys, removes nothing): tool-rail
  row → select mode (= TAB/F1–F7); palette chip → select material (= 0–9).
  Row geometry constants (`RAIL_*`, `PAL_*`) are shared by hit-test and draw.
- Removed `HUD_H`/`COL_HUD_BG`; added pane colours + `editor_layout` import.

**Verification**: `--auto` on `bake_demo` ran all 90 frames through the new
draw path (view-mode cycling included) and screenshotted a correct 6-pane
layout with the map cleanly clipped to the canvas (no bleed into chrome).

**Test `tests/test_editor_layout.py`** (headless, 15 cases): panes tile the
window exactly (no overlap / no gaps, areas sum to W·H) across 9 sizes incl.
sub-chrome; default-size adjacency; half-open `contains`; `pane_at` canvas
priority; canvas transform invertibility; **tile→screen→tile round-trip in the
canvas pane**; `fit_camera` centring. `run_editor` itself needs a real GL
context + a baked level (not headlessly constructible), so per the gate its
plumbing stays on `--auto` + these pure helpers.
