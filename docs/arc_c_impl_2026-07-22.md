## C0 — recon + panes shell

### As-is note (current map_editor.py architecture, mapped at C0)

`tools/map_editor.py` (~1.7k lines) is a single pyray (raylib) tool. All pure
geometry/writeback helpers live at module scope + in `tools/level_edit_common.py`
(palette, brush, `line_tiles`, `paint_tiles`, CSV save, `UndoRing`,
`art_px_to_tile`); the interactive part is ONE big function `run_editor()`
holding all state as locals + one `while not rl.window_should_close()` loop.
raylib has no input-injection API, so the loop is smoke-tested via `--auto`
(renders ~90 frames, cycles view modes, screenshots, exits) and the pure
helpers carry the unit tests (`tests/test_map_editor_tool.py`).

- **Main loop** (per frame): read modifier/mouse state → global keys
  (quit/mode/view/palette) → view (wheel-zoom / WASD+MMB pan) → cursor-tile
  resolve → per-mode input branch → undo/save → draw (world then HUD) →
  `--auto` plumbing.
- **MODES** = `("PAINT","ROOM","CORRIDOR","DOOR","SPAWN","LIGHT","WATER")`.
  Mode state is a single int `mode_idx`; `mode = MODES[mode_idx]`. TAB/Shift+TAB
  cycles, F1..F7 jumps. `cancel_transients()` drops drag/stroke state on every
  switch.
- **Input dispatch**: one big `if mode == "PAINT": … elif "ROOM": …` chain.
  Each branch reads `lmb/rmb/lmb_click/rmb_click/lmb_up` + mode keys. The
  `over_hud = mouse.y <= HUD_H` gate blocked edits when the cursor was over the
  top HUD strip; every editing branch is guarded by `not over_hud`.
- **Draw loop**: `to_screen(wx,wy) = ((wx-cam)*zoom)` full-window; baked
  texture (or material-colour fallback) → grid lines → mode cursor overlays →
  water overlay → spawn markers → light markers → HUD. View transform is
  `screen = (world_px - cam) * zoom`; `art_px_to_tile` is the inverse for the
  cursor. Preview is a live baked GPU texture (`bake_full` once, `bake_region`
  dirty-rect re-bakes, +1-tile margin for the edge16 neighbour contract).
- **Toolbar/HUD/status**: drawn as ONE opaque strip `rl.draw_rectangle(0,0,
  win_w,HUD_H)` at frame end — five text lines (level/grid/zoom/view; mode +
  material + per-mode extra; palette chips + undo depth; mode hint; global
  keybind help) + a transient `flash`/`flash_frames` status line below it.
- **level_lib usage (read+write, the single data layer)**: opens via
  `level_lib.open_level()` → `handle.data` (tilemap, spawns, lights,
  water_depth_q, raw_toml). Refuses v≠2 and no-`[bake]` (painted) levels.
  SAVE (Ctrl+S): `save_tilemap_csv` (own .bak) → `mask_water_to_open` guard →
  `level_lib.write_water_npy` → `handle.save({...spawn/light/water managed
  blocks...})` (ONE atomic temp+rename, one session .bak) → `bake_level`
  (rewrites `[art]`/`[bake]`, `write_bak=False`) → `handle.record_disk_state`.
- **Per-domain undo rings (C2 REPLACES these with a transaction log)**:
  1. `undo` = `UndoRing` (numpy grid snapshots) — shared by PAINT/ROOM/
     CORRIDOR/DOOR tile mutations.
  2. `spawn_undo` = `SpawnRing` (dataclass-list snapshots) — SPAWN only.
  3. `light_undo` = `SpawnRing` — LIGHT only.
  4. `water_undo` = `UndoRing` (numpy depth-grid snapshots) — WATER only.
  Ctrl+Z pops the ring for the CURRENT mode (spawn/light/water in their modes,
  else the tile ring). Rings are deliberately separate today so Ctrl+Z in one
  domain can't silently rewind another. Push points are scattered through each
  mode branch (before each mutating action / before each drag commit).
- **Global mutable state a panes refactor must respect**: `grid` (numpy,
  mutated in place + snapshotted for undo; the live baked textures
  `tex_diffuse`/`tex_normal` are kept in sync by `rebake_*`); `spawns`/`lights`
  (dataclass lists), `water_q` (int32 Q16.16 grid); the four `dirty_*` flags +
  their `*_bak_written` once-per-session guards; camera (`cam_x/cam_y/zoom`);
  stroke/drag transients (`stroke_active/pending/dirty`, `room_start`,
  `corr_start`, `spawn_drag`, `light_drag`, `anchor_tile`, `last_paint_tile`);
  `flash/flash_frames`, `esc_armed`. `preview_ppt` may differ from bake ppt
  (texture-cap divisor). All of this lives as `run_editor` locals — there is no
  editor object; a panes refactor works within that function.

### Impl note (as-built C0 — panes shell)

**New module `tools/editor_layout.py`** — the pure pane-layout abstraction (no
raylib import, fully headless-testable):
- `Rect(x,y,w,h)` with half-open `contains()` (adjacent panes never both claim
  a pixel).
- `compute_panes(win_w, win_h) -> {top_bar, tool_rail, canvas, palette,
  inspector, status_bar}`. The canvas is derived by subtraction so the six
  rects **tile the window exactly** (no overlap, no gaps) at any size; every
  dim is clamped ≥ 0 so a sub-chrome window still tiles. Layout: top bar (full
  width) · left tool rail · centre canvas · right column split palette(top)/
  inspector(bottom) · status bar (full width).
- `pane_at()` (canvas-first hit test), `screen_from_world`/`world_from_screen`
  (canvas viewport transform = old `(world-cam)*zoom` shifted by the canvas
  pane origin; exact inverses), `fit_camera` (centre world in the canvas).

**`tools/map_editor.py` rehosted onto the shell — zero editing-behavior change**:
- Camera now fits the world into the **canvas pane** (`fit_camera`) instead of
  the full window; `panes`/`canvas` recomputed each frame from the live window
  size (still resizable).
- `over_hud` kept its meaning but is now `= not over_canvas` (mouse over any
  non-canvas pane) — so all 14 `not over_hud` edit-gates are unchanged in
  semantics; canvas clicks still edit, chrome clicks don't.
- Cursor-tile, wheel-zoom and `to_screen` are **canvas-relative** (mouse offset
  by the canvas origin). Wheel-zoom is now gated to the canvas (scrolling over
  a pane no longer zooms; also avoids zooming around an off-canvas point).
- The world draw is wrapped in `begin/end_scissor_mode(canvas)` so the map
  clips to its pane; the old single HUD strip is replaced by five framed panes
  drawing the **same information** (top bar: level/grid/zoom/view; tool rail:
  the mode list, active row highlighted; palette: chips+names, selected boxed;
  inspector: `[MODE]` + material + per-mode extra + wrapped hint + undo depth;
  status bar: **mode · cursor tile · validator summary(flash) · unsaved dot ·
  registry-import banner slot** — the banner slot is empty in C0, C1 fills it).
- Pane click-routing added (mirrors existing keys, removes nothing): tool-rail
  row → select mode (= TAB/F1–F7); palette chip → select material (= 0–9).
  Row geometry constants (`RAIL_*`, `PAL_*`) are shared by hit-test and draw.
- Removed `HUD_H`/`COL_HUD_BG`; added pane colours + `editor_layout` import.

**Verification**: `--auto` on `bake_demo` ran all 90 frames through the new
draw path (view-mode cycling included) and screenshotted a correct 6-pane
layout with the map cleanly clipped to the canvas (no bleed into chrome).

**Test `tests/test_editor_layout.py`** (headless, 15 cases): panes tile the
window exactly (no overlap / no gaps, areas sum to W·H) across 9 sizes incl.
sub-chrome; default-size adjacency; half-open `contains`; `pane_at` canvas
priority; canvas transform invertibility; **tile→screen→tile round-trip in the
canvas pane**; `fit_camera` centring. `run_editor` itself needs a real GL
context + a baked level (not headlessly constructible), so per the gate its
plumbing stays on `--auto` + these pure helpers.

**Gate**: full suite `pytest tests -q` = **1176 passed, 22 skipped, 1 warning**
(warning pre-exists: an intentional zone authoring-warning in test_zones). Zero
goldens/digests touched (entity-digest, b6-logic-golden, unit-state-digest all
green). NOTE: this fresh worktree had no compiled `breach_physics` — built once
via `cpp/build_cpu_data.bat` (CPU, in-bounds: compile only, no cpp/golden
edits) so the sim tests collect; the `.pyd` is gitignored build output.

**For C1**: the registry-driven palette + inspector replace the `palette` and
`inspector` panes — geometry is already carved (`panes["palette"]`,
`panes["inspector"]`); reuse `PAL_PAD_Y`/`PAL_ROW_H` or replace them. The
status bar already reserves the **registry-import banner slot** (draw it at the
right of `status_bar`, left of the unsaved tag). SPAWN/LIGHT are still the
bespoke dataclass paths (untouched by C0) — C1 ports them onto `[[entity]]` and
deletes the bespoke paths; the four undo rings stay until C2's transaction log.

## C1 — registry palette + inspector

### Registry load + fallback (canon §1)

New module `tools/entity_editor_ui.py` (no raylib import, headless-testable):
`load_registry()` calls `import simulation.entities` then
`export_registry_json()` (rewrites `entity_registry.json`, repo root,
gitignored, as the new last-good — canon §1: "rewritten on every successful
launch") and returns `registry_payload()`. On ANY import-time exception it
falls back to reading the last-good `entity_registry.json` and reports
`ok=False` + the error string; the palette still renders from whatever the
last-good snapshot carried. Both failing (fallback file also unreadable) is
a loud `RuntimeError` — the one case the editor can't start from. An
`importer=` seam lets tests simulate an import failure without breaking a
real class; the semantics it exercises (escalation trigger 4) are
unchanged from canon §1 — only the test injection point is new.

Deliberately does **not** import anything from `simulation.entities` at
module scope (not even the `KIND_*` schema constants — schema.py's closed
vocabulary is duplicated as plain string literals instead): if the live
import is what's broken, this module — palette + inspector included — must
still work purely off the JSON fallback payload.

`map_editor.run_editor` calls `load_registry()` once at launch (no args —
the real repo-root file both ways); `registry_banner` is set from
`registry_result.error` and drawn in the status bar's reserved slot (red,
right of the validator/flash text, left of the `UNSAVED *` tag) whenever
`not registry_result.ok`.

### Registry-driven palette (tabbed)

The palette pane is now genuinely tabbed: **MATERIAL** (unchanged C0
content) and **ENTITY** (new), click-switchable at a small header row drawn
at the top of the pane (`PAL_TABS`, hit-tested by `rl.measure_text` so the
click target matches the draw exactly). `entity_editor_ui.palette_entries()`
returns one `PaletteEntry` (class name, class-initial glyph, a deterministic
generated colour chip — same golden-angle hue-walk recipe as
`level_edit_common._auto_rgb`, keyed by a hash of the class NAME since
entity classes have no small integer id) per class in the loaded registry
payload, **sorted by name**.

Scope call: the schema has no "placeable" flag — `INTANGIBLE` means "no
tile", not "not an instance" — so every registered class gets a palette
entry, not just the kickoff doc's four named examples (`door`, `light`,
`breach_site`, `extraction_zone`). The real registry today also surfaces
Arc B's logic/sensor/actuator/control classes (`decider`, `gate_and/or/not`,
`filter`, the six field/motion/clock sensors, `airlock_controller`,
`button`, `terminal`) this way. C1 only needs selection + a template
display to work (task spec); C3+ decide which classes get a dedicated
placement gesture vs the generic place-one, and can filter the palette
further then if that turns out to matter. Clicking a chip sets
`selected_entity_class`, which the inspector reads.

### Registry-driven inspector

`entity_editor_ui.inspector_rows(cls_payload, values)` renders one
`InspectorField` per declared schema field (schema order, not sorted): a
kind-aware `display` string (`format_field_value`) plus `editable` +
min/max/choices for a future widget. `KIND_LENGTH_M` fields show
`"{meters} m -> {tiles} tiles"` via `quantize_length_m` — the editor doc §4
exact rule, `floor(length_m * tiles_per_m + 1/2)` in `Fraction` arithmetic
(round-half-up, base `tiles_per_m = 3`), cross-checked in tests against
`simulation.entities.door.quantize_span_tiles` for the same inputs.

**Editable kinds in C1**: `int`, `q16`, `length_m`, `bool`, `enum`,
`float_render`, `color_rgb`. **Display-only**: `str`, `str_list`, `roster`,
`entity_ref` — map_editor.py has never had in-UI text input ("No in-UI
text input in v1" is its own standing rule; ids are auto-minted, never
retyped), and tag/roster assignment is explicitly later arcs' job (C4 tags,
C5 zone roster). No generic edit WIDGET ships in C1 either way: the only
class with live instances to edit is `light` (LIGHT mode, below), and its
existing bespoke keys already satisfy "editing a field updates the
instance" — building a second, generic editing path for zero other classes
(nothing else has a placement tool yet) would be speculative work with no
oracle. The inspector shows two things depending on state, first match
wins: (1) LIGHT mode with a light hovered → that instance's live fields
(`light_entity_port.light_entry_to_fields`); (2) an ENTITY-tab class
selected → that class's default template (`values={}`, so every field
reads its registry default); else the unchanged C0 mode/material/hint
content.

### The LIGHT port (Amendment A1) — bespoke path deleted, parity proven

New module `tools/light_entity_port.py`. `light.py`'s schema mirrors
`LightEntry` field-for-field **by design** (its own docstring says so), so
the port keeps every existing LIGHT-mode interactive line in
`map_editor.py` (B/C/R/E/P/X/H keys, drag, hover hit-test, the whole
~100-line block) **completely unchanged** — only the LOAD and SAVE
boundaries move:

- `EditableLight(LightEntry)` adds the one new fact a `[[entity]]` instance
  is mandatory to carry: `id`. It's a dataclass **subclass**, not a change
  to `level_loader.LightEntry` (out of the allowed surface anyway) — so
  every existing `dataclasses.replace(lights[i], ...)` call keeps working:
  `replace()` preserves the subclass and every field, `id` included,
  across every edit (verified directly, not just inferred).
- **`light_form(raw_toml)`** decides ONCE at load, from raw TOML alone:
  `"legacy"` when the file has any raw `[[light]]` block, `"entity"`
  otherwise — including a level with **zero** lights, since the bespoke
  `[[light]]` WRITER no longer exists to fall back to. This is not a
  migration: nothing legacy gets converted, because there is nothing
  legacy to convert.
- **`initial_editable_lights(lvl)`** seeds ids at load: entity-form levels
  keep their authored `[[entity]]` ids (`lvl.lights[i]` <-> the i-th
  `class == "light"` entity, in file order — level_loader's own
  construction order, and mixed forms hard-error so the two cases never
  interleave); legacy levels mint fresh `light_N` ids (nothing references a
  legacy light by id, so a fresh mint costs nothing).
- **`merge_light_entities(original_entities, lights)`** rebuilds the
  `[[entity]]` array for a save: pre-existing non-light entities (doors,
  zones — nothing edits those yet) keep their exact file position; each
  pre-existing light's slot is replaced by its current edited form or
  dropped if deleted; brand-new lights append at the end. This bounds a
  save's file-order churn to "what changed" — reshuffling would not be a
  correctness bug (canon §2: refs address ids, never positions) but would
  needlessly perturb the ENTITY_SECT_V1 digest row order for anyone who
  opens a mixed door+light level and saves.
- **`format_lights_for_save(light_form, lights, other_entities)`** is the
  one function `map_editor.py`'s Ctrl+S calls: returns `{"light": ...}` or
  `{"entity": ...}`, **never both**, never the family the level did NOT
  already use — the untouched family is simply omitted from
  `level_lib`'s `replacements` dict, and `level_lib` already preserves
  omitted families byte-for-byte (existing, tested behavior — no
  escalation needed, confirmed by `test_legacy_level_save_stays_legacy_form_no_entity_family`).

**Parity proof** (escalation trigger 5 — a bespoke-path DELETE can't reach
behavior-parity first): `tests/test_light_entity_port.py::
test_editor_authored_light_matches_legacy_authoring` builds one
`LightEntry` (static and beacon cases), writes it into a level TWO ways —
via legacy `format_light_lines` and via THIS port's
`merge_light_entities`/`light_to_entity_instance` + `format_entity_lines`
— reloads both through `level_loader.load`, and asserts the resulting
`LightEntry` values are dataclass-equal. This exercises the EDITOR's new
authoring code specifically (not just level_loader's pre-existing
`_light_entry_from_entity` alias contract, which `test_entity_format.py`
already covers).

**Known gap for C2**: `light_undo` (the bespoke `SpawnRing`) still holds
`EditableLight` snapshots exactly as before — it works today (verified:
`dataclasses.replace` + `SpawnRing.push`/`pop` are fully generic over any
dataclass) but per Arc C1's own scope it is NOT ported into a transaction
log; that's explicitly C2's job for every domain's ring, LIGHT included.

### Module layout

**New `tools/undo_log.py`** — pure, headless, no raylib import:
- `UndoContext(grids, collections)` — the live-state registry. `grids` maps a
  name to the numpy array (written in place via fancy indexing), `collections`
  maps a name to the dataclass list (written via slice-assign). Handles are
  refilled in place for the whole session, never rebound (§7).
- `GridCellsOp(grid_name, ys, xs, before, after)` — a delta on one grid
  (changed cells only). `undo/redo` = `grid[ys, xs] = before/after`;
  `bounding_rect()` (a re-bake HINT only); `nbytes` = the four arrays'
  (~16 B/cell).
- `CollectionOp(coll_name, before, after)` — a whole-list snapshot pair.
  `before`/`after` are `copy.deepcopy` lists (B1); `undo/redo` slice-assign a
  FRESH deep copy so the live list never shares mutable substructure
  (`EntityInstance.fields`/`.tags`) with the retained snapshot.
- `Transaction(label, ops)` — apply in order / invert in reverse order (§1.2);
  `rebake_rects()` yields `(grid_name, rect)` for its grid ops.
- `TransactionLog(ctx, depth=256, max_bytes=128 MB)` — the linear cursor + redo
  truncation + saved-marker dirty + front-eviction + the builder seam. Bounds
  are constructor args (C7) so tests pass a tiny ceiling.

**`tools/light_entity_port.py`** — added `unique_entity_id(prefix,
*collections)`, the B3 union id allocator scanning `lights ∪ entities ∪ …`
(kept `unique_light_id` — tests + `initial_editable_lights` still use it).

### The builder seam integration

Immediate-mode capture (§2.1): every gesture calls `log.begin(label)` +
`log.snapshot_grid(name)`/`log.snapshot_coll(name)` at its START, mutates live
state EXACTLY as before (the ~1.7k-line loop's mutation code is unchanged), and
`log.commit()` at its END extracts the delta vs the now-mutated state and
pushes ONE transaction (or drops it if empty). Grid ops use a **whole-grid**
`before != live` diff (B2 — never bounded by a gesture rect); per-gesture rects
(`stroke_dirty`) survive only as the live-preview re-bake hint. `commit()` is
the only log-mutation point. `cancel_transients()` (mode switch / Esc) commits
any open transaction — a no-op gesture drops, a real change is kept (the
blessed drag-commit-on-interrupt improvement, §2.4). `abort()` (reverts from
the retained before-copy) is on the surface for C4 but no C2 editor path needs
it (validation precedes every live mutation).

### What C3+ must do to register their ops (the extension pattern)

Reuse a primitive with a registered name; add a new grid/collection to the ctx
registry only for a genuinely new array/list. No third op type is needed.

- **C3 DOOR placement** = ONE transaction carrying BOTH a
  `GridCellsOp("material")` (stamp `MAT_DOOR_CLOSED`, id 7) AND a
  `CollectionOp("entities")` (the door entity) — the compound archetype
  (`test_compound_transaction_atomic_grid_plus_entity` pins it). Build it
  between one `begin("door")` and one `commit()`: `snapshot_grid("material")`,
  `snapshot_coll("entities")`, stamp + append, commit. Mint the door id via
  `unique_entity_id("door", lights, entities)` (B3).
- **C3 sensor / generic place-one** = `CollectionOp("entities")` only (no grid
  stamp); mint via `unique_entity_id`. Validate (solid-`sample_tile` refusal)
  BEFORE the first mutation, so a refused placement never opens a transaction.
- **C4 multi-select move / tag / clump-paste** = `CollectionOp("entities")`
  (+ `CollectionOp("wires")` once `wires` is registered) — the whole-list
  snapshot handles re-id + N-at-once for free. An id-changing op MUST carry the
  `wires`/tag `CollectionOp`s in the SAME transaction (§7 referential rule).
- **C5 zone/air paint** = `GridCellsOp("zones")`/`GridCellsOp("air")` — register
  those grids in `ctx.grids` only once allocated (they are `None` at load; a
  `GridCellsOp` on `None` would fail). A tool that resizes/crops a grid
  invalidates stored coordinates → it must reset the log (no Arc C tool does).
- **C6 wire add/remove** = `CollectionOp("wires")` after registering the
  `wires` collection in `ctx.collections`.

Constraint on any future op type (§6.3): store-and-assign only — never derive
its effect from state a sibling op in the same transaction writes, or
reverse-order inversion breaks.

### 1. DOOR tool

Replaces the OLD single-click legacy-`MAT_DOOR` stamp (`door_check`'s
consumer) entirely: DOOR mode now places a `door` `[[entity]]` and stamps
its span immediately. Click a straight wall-run tile (mirrors the OLD
`door_check`'s straightness gate, now MAT_DOOR_CLOSED-aware instead of
legacy-MAT_DOOR-aware) to anchor a drag; a plain click (no movement) uses
the schema default (1.0 m -> 3 tiles); dragging extends FORWARD from the
anchor (the anchor is always door.py's own leftmost/topmost convention, so
it never needs reassigning) toward the cursor, clipped at the first tile
that isn't a stampable wall tile — the run's own end, an existing door, or
the grid edge (no hard minimum; a run shorter than the target just yields a
shorter door). **O** toggles the placement default between closed/open
(default closed); RMB cancels an open drag. A span narrower than the
default marine footprint (`DEFAULT_FOOTPRINT = 3` tiles) flashes a WARNING,
never blocks. Release commits ONE `Transaction` — `GridCellsOp("material")`
(`MAT_DOOR_CLOSED` for closed, `MAT_AIR` for open, across the whole span)
+ `CollectionOp("entities")` (the door instance) — via
`door_entity_port.commit_door_placement`, the C2 archetype exactly as its
as-built note anticipated. `door_tool_availability(tile_size_m)` is checked
ONCE at launch (a non-integer tiles-per-meter level has no defined door
quantization, a6 doors design §3 S1) so a bad level flashes a clear refusal
instead of the quantizer raising mid-drag; every level in the tree today
passes (`tile_size_m = 0.333` -> exactly 3 tiles/m).

**Span-parity guarantee**: `door_entity_port` never computes a tile list of
its own. `plan_door_span` derives the tile COUNT by walking the live grid,
then calls `simulation.entities.door.base_span` — THE canonical function —
with the resulting `length_m` to get the tiles it actually stamps.
`length_m_for_tiles(n, tile_size_m)` (= `n / door.tiles_per_m(tile_size_m)`,
one float division) is proven, not assumed, to round-trip through
`door.quantize_span_tiles` for every tile count tested, because `n /
tiles_per_m` sits exactly AT the target integer when multiplied back —
never near a round-half-up tie (those fall at `k + 0.5` tiles) — so neither
the float division's ~1e-16 error nor the toml `repr()` round-trip
(`level_lib._fmt_value` writes floats via `repr`, the shortest EXACT
round-trip form) can cross a tie boundary. `tests/test_door_entity_port.py`
pins this directly (parametrized over several tile counts) plus the editor
doc §4 trap by name: quantizing 0.5 m ONCE at base res then replicating by
`--res 2` gives 4 tiles (`2 * 2`); re-deriving from meters at the SCALED
`tile_size_m` instead (`0.333/2`) hard-errors (non-integral tiles/meter,
a6 doors design §3 S1) — proof the "replicate, never re-derive" rule is
load-bearing, not just documented.

The old `door_check` function (legacy `MAT_DOOR` gate) is left in place,
unused by the interactive tool now, purely as a tested pure primitive
(`tests/test_map_editor_tool.py` still exercises it directly) — no test

### New module — pure, headless, no raylib import

**`tools/entity_selection.py`** is the whole transaction-committing core;
`map_editor.py`'s SELECT mode is a thin interactive shell over it (smoke-
tested only via `--auto` — raylib has no input-injection API, matching

### The selection model

A selection is a `set` of ids over **`lights` u `entities`** — never
`spawns` (units are not entities, canon §0/A1; SPAWN keeps its own bespoke
mode, untouched). `find_instance(id, lights, entities)` resolves an id to
`(collection_name, index)` FRESH every use rather than caching a stale
index, since delete/paste can shift indices mid-frame. Hitboxes
(`instance_tiles`): a light is its tile-floored center point; a DOOR is its
**whole span**, recomputed via a new `door_entity_port.instance_span`
(never a parallel calculation — the exact parity rule C3's placement tools
already followed, so a selected door's highlight always matches its
stamped material); any other positioned class is its one `(x, y)` tile; a
positionless class (no `x`/`y` — the logic nodes) has no hitbox and is only
reachable through select-by-class. `hit_test` (topmost, entities before
lights), `box_select` (any hitbox tile inside the rect), and
`select_by_class` (every instance of a class, the only way to reach a
positionless one) are the three lookups the interactive gestures (click,
shift-click toggle, box-drag, the `A` key) sit on top of.

### Move / delete — one compound transaction, referential integrity

`commit_move_selection`/`commit_delete_selection` each build ONE
`Transaction`: `GridCellsOp("material")` (a selected door's OLD span clears
to `MAT_AIR`, a moved door's NEW span re-stamps per its authored
`initial_state`; a deleted door's span just clears) + `CollectionOp` on
whichever of `"lights"`/`"entities"` actually changed. Move pre-validates
(`plan_move_selection`) that a door's new span stays on the grid BEFORE any
mutation, refusing (no-op) otherwise. Delete additionally carries
`CollectionOp("wires")`: any wire whose `from` or **non-tag** `to` names a
deleted id is dropped in the SAME transaction (the C2 §7 referential-
integrity mandate — undo restores the entity AND its wires together, never
strands one on the other); a tag-target `to` (`tag:name.input`) is never
"touched" since its membership resolves from live tags at load, nothing to
strand.

### Assign-tag-to-selection

`commit_assign_tag` adds a tag to every selected instance's `tags` in ONE
transaction (idempotent per-instance; a selection already fully tagged is a
genuine no-op — `commit()` drops it). **`EditableLight` gained a `tags`
field** (`tools/light_entity_port.py`) so lights can carry tags exactly
like `EntityInstance` — `initial_editable_lights` now recovers a
entity-form light's authored tags from `lvl.entities` (the pre-filter list)
before they're dropped from the `lights`/`entities` split, and
`light_to_entity_instance` writes `tags=l.tags` (was hardcoded `()`) so a
tag survives a save.

### Inspector field edits — the generic mechanism

`commit_field_edit(log, grid, lights, entities, id, field_name, new_value,
tile_size_m)` is ONE transaction for ANY field of ANY class (int/q16/
length_m/bool/enum/float_render/color_rgb — the interactive nudge/cycle
keys live in `map_editor.py`'s SELECT block, mirroring LIGHT mode's own
inline R/E/P/X/H style, generalized via `entity_editor_ui.inspector_rows`'
bounds/choices metadata): a door edit to `length_m`/`orientation`/
`initial_state` re-stamps its grid span in the SAME transaction; a field
the instance did NOT already author is added to `authored_keys` so the
edit actually survives a save (else `format_entity_lines`'s "defaults are
never materialized" contract would silently drop it); an `id` edit is
refused BEFORE any mutation on a collision across `lights` u `entities`
(canon §2). `str id` and `str_list tags` edits route through this same
function (id via a scoped text-entry gesture, see below) / through
`commit_assign_tag` respectively — **`roster` stays a genuine gap**, per
C1's own note ("roster editing rides zone placement, C5"): no zone
instance can exist yet (C3 refuses to place a class with an unfillable
required field), so there is nothing to wire a roster widget to; the
mechanism is generic enough that C5 can call `commit_field_edit` for it
unchanged.

### Clump copy/paste — the poor man's prefab

`compute_clump_copy(ids, lights, entities, wires)` snapshots every selected
instance (deep-copied) plus every **internal** wire (both endpoints in
`ids`, non-tag target). `commit_clump_paste(log, grid, lights, entities,
wires, clump, delta_tx, delta_ty, tile_size_m)` is ONE compound
transaction:

1. Mint a NEW id per member via `unique_entity_id(class_name, lights,
   entities)` (the same allocator every placement tool mints under) —
   scanning `lights`/`entities` which this function appends to
   PROGRESSIVELY, so two same-class members in one clump never collide
   with each other either; builds an old→new id map.
2. Duplicate each member with its id remapped and position offset by the
   paste delta (`clump_anchor_tile` gives the bbox top-left so the offset
   preserves internal relative layout); `tags` copy verbatim; a pasted door
   re-stamps its NEW span (out-of-grid cells silently skipped).
3. Duplicate each internal wire with BOTH endpoints remapped through the id
   map.

Returns `(Transaction, new_ids)` so the caller can select what was just
pasted. **Tag-target wires are dropped at COPY time already** (documented
simplification, not a bug): a `to = "tag:name.input"` wire's membership
resolves from live tags at LOAD, never stored on the wire, so once a
pasted member's tags are copied verbatim it already "reaches" any tag wire
touching that tag for free — no tag-expansion machinery needed here. C6
(wire tool + LOGIC overlay + tag badges) owns any richer tag-aware clump
behavior. Undo/redo reverts entities + wires + grid atomically (one
`Transaction`, proven directly and via a copy→paste→save→reload round trip
through `level_lib`).

### 1. Positionless-entity canvas layout (the C3/C4/C5 forward pointer, closed)

`wire_tool.positionless_layout(entities, zones, grid_shape)` gives every
positionless entity (no `x`/`y` in its schema at all — `decider`/
`gate_and`/`gate_or`/`gate_not`/`filter`/`clock`/`airlock_controller`, plus
the zone classes `breach_site`/`extraction_zone`) a deterministic clickable

- Everything else — **true logic nodes**, and a **zone instance with no

### 2. The two-click wire gesture — NEVER a drag

`wire_tool`'s pending-wire state is a **plain dict** (matching the
`entity_drag`/`select_box` convention `map_editor.py` already uses for
in-progress gestures that never open a log transaction on their own, §6.2):

- `begin_pending_wire(from_id, cls_payload)` — click 1. Defaults
  `signal_idx` to `primary_signal`: the first NON-`alive` signal
  (`all_signals()`'s own order is always `(alive,) + cls.SIGNALS`, canon
  §8), or `alive` itself for an `alive`-only class (`button`/`terminal`/
  `light` — "inert but format-reserved"). `[`/`]` (map_editor: `cycle_
  pending_signal`) cycle it while the target is still unset.
- Pan/zoom/scroll stay live throughout (editor doc §8's explicit spec) —
  nothing in the WIRE mode block touches the camera; it is simply never
  gated on `wire_pending`.
- `set_pending_target_id(pending, to_id, cls_payload)` — click 2 (the id
  form). Locks `inputs` to the target class's declared input list;
  refuses (`(None, reason)`, pending kept alive so the user can pick a
  DIFFERENT target) when the class declares no inputs at all (e.g. a field
  sensor) — a structural refusal, not a loader round-trip.
- `set_pending_target_tag(pending, tag_name, lights, entities,
  registry_payload)` — the **tag-target form** (editor doc §8: "offer this
  when wiring to a tagged group"). `tag_input_names` computes the
  **intersection** of every CURRENT member's declared inputs (Arc B §1b:
  "a tag member lacking the input hard-errors", so only a common input
  could ever commit) — empty when the tag has no members yet, or no input
  is common to all of them (both legitimate "nothing to offer", not
  errors). In `map_editor.py`, **T** (not G — G is already the global grid
  toggle) cycles through `wire_tool.all_tags()` while a source is pending
  and no target is locked yet.
- `cycle_pending_input` / `pending_ready_to_commit` / `pending_wire_strings`
  round out the machine. **Commit timing**: a target with `<= 1` input
  commits IMMEDIATELY on the target click — genuinely "two clicks, done";
  a target with multiple inputs opens an input-picking sub-phase (`[`/`]`
  cycle, **Enter** confirms) rather than requiring a third click, since a
  click is already spent choosing the target itself.
- **Esc cancels the pending wire at any point** (the global Esc block:
  `elif wire_pending is not None: wire_pending = None`, checked BEFORE the
  dirty-quit-arm logic, mirroring how C4's `text_entry` already claimed
  that slot) — never the "UNSAVED — Esc again to quit" prompt while a wire
  is mid-gesture.

### 3. Validation — REUSED, not re-derived

`wire_tool.validate_wire(from_id, signal, to_spec, input_name, lights,
entities, spawns, existing_wires)` calls **straight into
`level_loader._parse_wires`** (module-qualified reference to the private
loader function — the exact precedent `zone_entity_port.
zone_binding_summary` set for `_validate_zone_binding`, not a new pattern):
source-signal existence, target-input existence (incl. "every tag member
must declare it"), and the unit-reference hard error (canon §3e) are ALL
the loader's own frozen §1b rules, never reimplemented. Lights fold in via
`light_entity_port.light_to_entity_instance` so a wire can legally touch a
light's free `alive` signal. A cheap liveness pre-check (`from_id`/
non-tag `to_spec` must resolve to a live combined id) runs BEFORE the
loader call — the interactive tool can only ever click a live id, so a
"dangling" candidate is refused directly rather than exercising the
loader's file-authoring "warn + drop" allowance (that allowance exists for
a hand-edited file referencing something deleted elsewhere; an editor
gesture pointed at a selected id should never silently author a wire that

dedicated test makes an entity id COINCIDE with a `[[spawn]]` unit's name
(both live), and confirms `_parse_wires`' unit-rejection still fires.

`CollectionOp("wires")` transaction (§6.2 validate-before-mutate — no
transaction opens on a refusal, the same contract DOOR/sensor placement
follow). `commit_remove_wire` is the symmetric one-transaction delete.

### `tools/rasterize_icons.py` — the constrained SVG subset

`rasterize_svg(path) -> PIL.Image.Image` parses one `<svg viewBox="minx
miny w h">` (viewBox is REQUIRED and must be square — one scalar scale
factor applies uniformly to geometry AND stroke widths, sidestepping
non-uniform-scale stroke semantics SVG doesn't sanely define anyway) and
renders its direct children only (no `<g>`/`<defs>`/`<use>`/transforms —
kept out to keep the renderer's behaviour obvious by inspection, not
because they'd be hard to add later):

- `<rect x y width height rx?>` — rounded via `ImageDraw.rounded_rectangle`
  when `rx` is present (uniform radius only; SVG's separate `ry` is not
  read).
- `<circle cx cy r>`, `<ellipse cx cy rx ry>` — `ImageDraw.ellipse`.
- `<line x1 y1 x2 y2>` — stroke only (a line has no fill in real SVG
  either).
- `<polyline points="...">` / `<polygon points="...">` — matches real SVG
  fill/stroke semantics exactly, not a simplification: FILL always treats
  the point list as implicitly closed (a polyline fills exactly like a
  polygon would); STROKE only follows the explicit segments — a polyline's
  stroke never closes the last point back to the first, a polygon's always
  does. Pinned directly by two tests
  (`test_polygon_is_implicitly_closed_for_both_fill_and_stroke` /
  `test_open_path_stroke_does_not_close`) that sample a specific pixel
  rather than trusting a visual read.
- `<path d="...">` using ONLY `M`/`m`, `L`/`l`, `H`/`h`, `V`/`v`, `Z`/`z`
  (both absolute and relative; the relative forms track a running current
  point). ANY other command letter — `C`/`S`/`Q`/`T`/`A` in either case —
  raises `UnsupportedSvgError` immediately, by name, via an explicit
  character scan over the raw `d` string (not just "the regex didn't
  match" — a letter the tokenizer regex silently skipped would otherwise
  vanish rather than error, so the scan is a second, independent net).
  Fill/stroke follow the same open-vs-closed rule as polyline/polygon
  (closed = ends in `Z`).
- `<text x y font-size fill>GLYPH</text>` — single glyph, centered on
  `(x, y)` (hardcoded `anchor="mm"`, not read from
  `text-anchor`/`dominant-baseline` attributes — those aren't parsed).
  Uses `ImageFont.load_default(size=...)` — Pillow's OWN bundled font
  (Pillow ≥10.1), never a system-font lookup, so a `<text>` icon renders
  identically regardless of what fonts happen to be installed on whatever
  machine re-rasterizes it. **None of the 21 authored icons use `<text>`**
  (by choice, to keep the committed PNGs' cross-machine determinism story
  simpler — see the freshness-test caveat below); the element is
  implemented and unit-tested (`test_supported_primitives_render_without_
  error`) for future use.
- Presentation attributes on every shape: `fill` (colour name from a small
  hardcoded set, `#rgb`/`#rrggbb`, or `none`; SVG's own default is
  `black`), `stroke` (SVG default `none`), `stroke-width` (scaled like
  geometry; default `1`), `opacity` (0..1, multiplies both fill's and
  stroke's alpha; default `1`). No CSS `style="..."` attribute at all —
  every icon spells out `fill`/`stroke` explicitly.

Any element tag, path command, or colour literal outside this subset
raises `UnsupportedSvgError` with the offending token named in the
message — by design (module docstring: "a silently-wrong icon is worse
than a build failure"). Output is fixed 64×64 RGBA, rendered at 4×
supersample (256×256 canvas) then downsampled with `Image.LANCZOS` —
deterministic (no randomness anywhere; two calls on the same file, same
Pillow install, produce pixel-identical output, pinned by
`test_deterministic_two_rasterizations_are_pixel_identical`).

CLI: `python tools/rasterize_icons.py` (no args) regenerates every
`art/entities/icons/<class>.png` from its `.svg` sibling via
`regenerate_all()`. This is a DEV-ONLY step — the editor runtime never
imports or calls anything in this module; `map_editor.py` only ever reads
the already-committed PNGs (see below).

### Freshness test — `tests/test_rasterize_icons.py` (66 cases)

**Portability caveat, noted not solved (matches every other pixel-drawing
concern in this renderer, not a new risk)**: the freshness test's
byte-identity check is only guaranteed within ONE Pillow install (the
`data` conda env, here) — a differently-versioned Pillow elsewhere could
render `rounded_rectangle`/`ellipse` antialiasing (or, if ever used,
`load_default`'s bundled font) fractionally differently and the freshness
test would then legitimately fail on THAT machine until the PNGs are
regenerated there. This is a property of "commit rendered pixels, test
them against a live renderer" generically, not something C8 introduced or
could remove without dropping the freshness guarantee entirely; avoiding
`<text>` in every authored icon removes the one extra font-rendering
degree of freedom from that risk.

### Palette wiring — PNG preferred, chip fallback permanent, loaded once

`entity_editor_ui.icon_png_path(class_name, *, icons_dir=None) -> Path |
None` is the one new pure function (headless-tested, no raylib import):
`art/entities/icons/<class>.png` if it exists, else `None`. It does not
decide how to draw anything — that stays `map_editor.py`'s job, matching
the existing split (this module is the pure logic half; the raylib loop
is smoke-tested only).

`map_editor.py` adds `_load_entity_icon_textures(entity_palette) -> dict`
(class name → GPU texture, built via the pre-existing `_texture_from_rgba`
helper — same one `tex_diffuse`/`tex_normal` already used, now fed a PNG's
`np.asarray(Image.open(...).convert("RGBA"))` instead of a bake result)
and calls it **once at launch, right after `tex_diffuse`/`tex_normal` are
built** — NOT where `entity_palette` itself is constructed, which is
BEFORE `rl.init_window()`. That ordering bug was caught immediately: GPU
texture creation before a live GL context segfaulted the very first
`--auto` smoke run (`rl.gen_image_color`/`load_texture_from_image` need an
initialized window/GL context, the same reason the pre-existing
diffuse/normal textures are built post-`init_window` and not earlier) —
moving the call fixed it outright, confirmed by a clean 90-frame `--auto`
run afterward. Textures are unloaded at shutdown alongside
`tex_diffuse`/`tex_normal` (`rl.unload_texture` per cached entry).

The ENTITY-tab palette draw loop (`tools/map_editor.py`, the
`palette_tab != "MATERIAL"` branch) now checks
`entity_icon_textures.get(pent.class_name)` first: if present, draws the
64×64 icon texture scaled to the existing 14×14 chip footprint
(`rl.draw_texture_ex(icon_tex, ..., 14.0 / icon_tex.width, ...)`, so the
row layout is pixel-identical to before); if absent, draws the EXACT same
chip-rectangle + class-initial code C1 shipped, unchanged. Textures load
once into a dict at launch, never per frame.
